# recipe-runtime: native port of `quant_table.py`, `estimate_vram.py` and `rank_recipes.py`

Package `recipe-runtime` (unpublished, no `license` field, like the other owner packages) at
`.claude/skills/vllm-recipe-explorer/rust/runtime`. It depends only on the common `agent-runtime-support` package (path
`../../../../rust/runtime-support`, checked with `cargo metadata`/the locked build) and on the same locked `num-bigint` 0.4.8 and
`num-traits` 0.2.19 the common package locks (needed directly for the arbitrary-precision integers of the formulas). No
dependency on the benchmark skill, no regex, network or TLS crate, no Python and no source evaluation anywhere. The call chain
quant to estimate to rank is plain in-process Rust. The package is not connected to any caller: the Python compatibility
adapters, shell launchers and the rewiring of `recipe.py`, `parse_model_config.py` and `crosscheck_model_card.py` belong to
Root and were not verified here.

## Design

* `pyexpr`: the dynamic-typing layer (`int()`, `float()`, `.get`, `[key]`, `*`, `-`, `/`, ordering across `bool`/`int`/`float`,
  string/list repetition, exact integer true division by a power of two, `str.strip().lower()` that is safe for lone
  surrogates). Every failure is the exception class and message CPython raises, built from the common `Failure`/`PyException`.
  The recipe formulas use definite `BigInt`/`f64` values after each original `int(...)`/`float(...)` conversion and `PyValue`
  only where the original handled a caller's value (`tp`, `budget_gib`, `safety_margin`, `serve_bpw`, `quantization`).
* `quant_table`, `estimate_vram`, `rank_recipes`: the business functions with the original names, defaults, argument order and
  evaluation order; tables and constants are typed arrays in the original order.
* `operations`: the importable functions by `module.function` name with Python's argument binding (positional, keyword,
  defaults, CPython 3.12's `TypeError` texts for a wrong call). `api` and the benchmark program use it; the business modules do not.
* `cliparse` + `cli`: the slice of `argparse` the three programs use (abbreviations, `--opt=value`, `-h`, int/float types, required
  options, one required exclusive group, `ambiguous option`, usage wrapping and `HelpFormatter`/`textwrap` layout at the
  `COLUMNS` width, default 80, minus 2) and the three `main`s with the original `.py` program names.
* Programs: `quant_table`, `estimate_vram`, `rank_recipes` (the original command lines), `recipe_numeric_api`
  (`constants`, `evaluate-jsonl`) and `recipe_numeric_bench` (frozen post-quality measurement, **not run here**).

Behaviour kept on purpose: `float(num_params) * bpw` fails with the interpreter's `TypeError` for a missing or text
`serve_bpw`, and a `None` weight factor is an `unknown_quant_method` result, not an error; integers are never clamped; `int()`
truncates and `//` floors as the original does; the hybrid layer count falls back to all layers unless it is a plausible
`0 < n <= total` (an infinite count is the uncaught `OverflowError`); the 1.02 block-alignment buffer is applied to the float
of the integer product and truncated; ranking is a stable sort of the passing results by `(headroom, max_model_len)`
descending (ties keep candidate order); `int / int` uses one correct rounding; the report pads by code points.

## R23TTY: terminal width and the TTY output path (2026-11-06)

**Bug.** `quant_table --help` on a real terminal with `COLUMNS` and `LINES` unset: the original (`shutil.get_terminal_size`, used by
argparse's `HelpFormatter`) asks the terminal on standard output and laid the help out for 40 columns (778 bytes, saved original
`r23-tty-reference/original.stdout`); the held v2 read only `COLUMNS`, assumed 80 and printed 643 bytes.

**Fix.** `cliparse::effective_columns(COLUMNS)` mirrors `shutil.get_terminal_size()[0]`: the environment value when it is a positive integer by
Python `int()` rules (`+40`, ` 40 `, `4_0` accepted; `0`, negatives, `4.0`, `0x28`, empty and text rejected); otherwise the width the terminal on
descriptor 1 reports; otherwise (not a terminal, closed, or 0 columns) 80. `HelpFormatter` still subtracts 2 (`terminal_width`). The three
commands call it; the library entry points keep their explicit `columns` argument (`None` = 80, no query), so API/unit cases stay deterministic.
Standard error is never asked (CPython asks `sys.__stdout__`). The query is `terminal::stdout_columns`, one `ioctl(1, TIOCGWINSZ, &winsize)`
declared locally for Linux x86_64 and aarch64 (`TIOCGWINSZ` = 0x5413, `struct winsize` = four `u16`), with the SAFETY argument at the call; no
new dependency, no `stty`/Python/shell, `COLUMNS` is never set by the program.

**Output path.** `stdio::TextStdout::line_buffered` models `TextIOWrapper.write`'s `needflush` (a write containing `\n` or `\r` flushes the
text layer, the byte layer and the descriptor); `cli::emit` enables it when `stdout().is_terminal()`. `cli::Run.writes` carries the original's
write events (help = one write; `quant_table` text = text and newline per line). `/dev/full` stays 120 / 120 / 1 and the API write failure 1 (no
`let _ =` or panic added to those paths).

| original | Rust | registered check |
|---|---|---|
| `shutil.get_terminal_size` (COLUMNS, then `os.get_terminal_size(fd 1)`, then fallback 80) | `cliparse::effective_columns`, `terminal::stdout_columns` | `recipe_tty_cases`: unset env on a 40-column pty = saved original bytes; `COLUMNS` 40/` 40 `/`+40`/`4_0` on a 120-column pty = same; `""`/`abc`/`0`/`-5`/`4.0`/`0x28`/`40 40` on a 40-column pty = same; 80-column pty, 0-column pty and a pipe (with or without junk `COLUMNS`) = one 80 layout; estimate usage error (stderr on a pipe) sized by the stdout terminal; the other two programs; a text result on a pty |
| `sys.stdout` line buffering on a tty | `stdio::TextStdout::line_buffered`, `cli::emit` | `a_line_buffered_stream_reaches_the_sink_at_each_newline_not_at_exit` (unit) |

The pty checks run in-process on a private pseudo-terminal (`posix_openpt`, `ptsname_r`, `TIOCSWINSZ`, raw mode through `cfmakeraw` on an oversized
termios buffer); no global terminal setting is touched.

master, 1 for the flagless one, 0 after it is closed). An earlier version of this guard opened the flagless control inside the shared parallel-test process, where
the other cases could have inherited it for a moment; the control now never exists there, and the suite is not serialised.
No production code, `Cargo.toml` or lock changed. Run (release): `cargo test --release --test recipe_tty_cases` = 8 passed, 0 failed, 2 ignored (the two

## R23b: borrowed argument binding (2026-11-06)

**Cause candidate (from the official 36-call measurement: pure `quant_table.vllm_quant_bpw`, `estimate_vram.estimate`, `rank_recipes.rank` slower than Python).**
`operations::Function::call` bound every call through `bind`, which deep-cloned each supplied `PyValue` (whole parsed and candidate trees included)
before a read-only body ran. Python binds the same objects (a reference count), so the copy has no original counterpart. The benchmark, its expected
values, workload and timed boundary are untouched.

**Change (`src/operations.rs` only).** `Function::bind_borrowed` returns `Arguments<'a>`: the supplied arguments are `&'a PyValue` borrowed from the
caller's slices, and the defaults needed by this call are created and owned inside `Arguments` for as long as the body runs (inline storage for the 8
parameters of the largest function and 3 defaults, both enforced for all 19 by a `const` assertion that also requires the defaulted parameters
to come last; no allocation for the slots). Bodies read `a[i]` through `Index`, so they
and the business modules are unchanged; the body type is `fn(&Arguments<'_>)`; the references cannot outlive the call (the lifetime ties them to the
caller's arguments) and nothing is cached, shared or mutated (no `unsafe`, no interior mutability). Binding order is as before: positionals that fit, the
keyword walk in order (unexpected or repeated keyword first), then surplus positionals, then missing parameters, with the same `TypeError` texts; the
counts and the repeated-keyword text are only built on the failing path. `bind` stays as the owned adapter (clones what `bind_borrowed` borrows); `call`
uses the borrow. `bench.rs`/`api.rs` and every other file are unchanged.

**Registered checks** (`recipe_binding_cases`, new, 5): all 19 functions fit and agree between the borrow and the owned adapter; supplied positional and
keyword arguments are the caller's own objects (`ptr::eq`) while a default is a fresh owned object; defaults apply, a keyword overrides one, and the explicit
spelling of the defaults gives the same value; nested inputs (and a ranked result fed to `render_report`) are unchanged after a call, even a failing one, and
a result outlives its arguments; unexpected-keyword before repeated-keyword before surplus-positional before missing, with CPython's messages.

**Run (release, `--offline --locked`, own target directory).** `recipe_binding_cases` 5 passed (run after the final form of the change; the first form, with 8 default slots, was replaced before the final runs); saved API 255 (`every_saved_function_call_is_reproduced_by_one_api_process`) 1
passed; `recipe_v2_cases` the signed-int 6 calls, boundary command lines 4, order 3, keyword-before-positional and CRLF: 5 tests passed; `recipe_formulas` 7 passed
(formulas, hybrid layers, feasible limits, call-binding errors, equal headroom, record protocol, constants). Not run by this change: the CLI 24 (the command
lines do not use `operations`), the `/dev/full` and PTY tests, the two benchmark tests, any original execution or timing. `fmt --check` and
`clippy --all-targets -D warnings` clean; default `release --lib --bins` last. **No speed is claimed**; Root's measurement decides.
