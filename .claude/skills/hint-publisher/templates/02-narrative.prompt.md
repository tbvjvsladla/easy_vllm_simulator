## 2.4 오진과 정정
<!-- PROMPT
질문: 계보 중 무엇을 잘못 진단했고, 어떻게 정정됐으며, 지금 그 주장의 지위는 무엇인가?
읽을 것: 하네스 교정 · 재판정 testlog · 캠페인 사후감사 · 후속 plan 의 "근거 사실" 절 · SUPERSEDED 헤더가 붙은 문서와 그 후속 · report 의 각주(가설 강등) · 교정 묶음 문서(항목 id 가 붙은 교정 목록 — 예: 하네스 교정 R0~R10)
블록: misdiagnosis
필수 발췌: 1
기재: 오진마다 `kind: misdiagnosis` 블록 + 1~2문단 산문. 정정 근거는 출처로 단다. 이 절에 `> [원문]` 발췌는 **최소 1개**(린터가 센다) — 오진마다 발췌하는 것은 **원래 주장이 짧을 때만** 권장한다. 여러 발췌보다 오진의 핵심을 보여 주는 선명한 하나가 낫다(서명 필드가 이미 원문 조각이다 · 1차 발행에서 오진마다 발췌해 02 가 99KB 가 됐다).
  반드시 훑을 것 — 원인을 잘못 짚은 판정(예: hang 을 모델 문제로 봤으나 호스트 워치독이었다) · 실행하지 않은 셀·회차에 사인(원인)을 기재한 것 · 도구 · 하네스 결함이 수치나 판정을 왜곡한 경우(루프라인 산식 결함 · 가중치 합산 오류 · 설정 번역기 부재 — 정정 전후 수치를 함께 · 그 결함이 무엇을 놓쳤는지(예: 측정이 자기 물리상한을 넘었는데 검출되지 않았다)) · 검증 술어 자체의 오류(예: 토큰 정확일치 기준을 버리고 다른 술어로 교체) · 다른 셀 · 다른 회차의 값이 섞여 든 주장 · 이전 발행물(옛 태그 · 옛 리포트)이 배포한 틀린 사실 · 가설로 **강등된** 기전(처방으로 쓰면 안 된다 — 현재지위를 적는다).
  계보에 **교정 묶음**(항목 id 가 붙은 교정 목록 — 예: 하네스 교정 R0~R10)이 있으면, 그중 이 셀의 판정 · 수치 · 이름을 바꾼 항목을 **id 로** 나열한다(`- <묶음 문서 stem> <항목 id> — 이 셀에서 바뀐 것 — 전 → 후`). 이 셀과 무관한 항목은 적지 않되, 묶음을 훑었다는 사실(검토한 항목 수)은 적는다.
  현재지위 = **원래 주장**(서명에 옮긴 당시 주장)의 지위다 — 반증 = 원래 주장이 거짓으로 확인됐다 · 확증 = 원래 주장이 참으로 확인됐다 · 가설(강등) = 원래 주장(기전)이 확인되지 않아 가설로 내려왔다 · 미결 = 아직 가르지 못했다. 정정된 이해의 지위가 아니다(정정된 이해는 `해소` 칸).
  형식 예시(현재지위는 권장 필드 · 서명은 당시 주장 또는 관측의 원문 조각 — 조각마다 공백 제외 12자 이상):
```hint-event
id: M1
kind: misdiagnosis
증상: <당시 무엇이 관측됐나>
서명: "<당시의 틀린 주장 또는 관측 서명 — 출처 원문 그대로>"
원인: <왜 잘못 진단했나>
해소: <정정된 이해>
검증: <정정을 확정한 문서 stem §절>
전이등급: judgment
현재지위: 반증        # 확증 | 반증 | 가설(강등) | 미결
출처: [<오진 문서 stem> §<절>, <정정 문서 stem> §<절>]
```
필수 필드: id · kind · 증상 · 서명 · 원인 · 해소 · 검증 · 전이등급 · 출처 (현재지위 권장) · 교정 묶음이 있으면 이 셀에 영향을 준 항목 id 목록
금지: 강등된 가설을 처방처럼 적기 · 정정 없이 옛 주장만 옮기기 · 정정 근거를 기억으로 적기 · "틀렸다" 만 적고 교정 근거를 생략하기 · 정정 전 수치(뒤 문서가 고친 수)를 이 페이로드의 목소리로 다시 적기 · 현재지위를 정정된 이해의 지위로 적기(원래 주장의 지위다) · 교정 묶음을 "여러 교정" 으로 뭉개기(항목 id 로)
