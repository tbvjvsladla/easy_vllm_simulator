## 한 문장

**메인이 단독으로 관리하고, 서브는 부하가 싱크된 분산추론 컨테이너의 한 칸이다.** 자율성을
독려하지 않는다 — 집단 연산은 lockstep 이고, 한 칸이 독자 판단을 하면 그것은 자율이 아니라 비정합이다.

## 전략 다섯

1. **부하 싱크로가 목표다.** 타겟 모델을 두 노드에 최대한 균등하게 실어 분산추론 컨테이너를 구동한다.
   비대칭은 성능 손실이 아니라 **집단 연산의 대기**로 나타난다.
2. **컨테이너 동기화는 Ray 워커를 전제로 설계한다.** 동기 대상은 이미지가 아니라 **집단 연산 ABI
   3종**(vLLM git SHA · torch · driver)이다. 각 노드가 자기 이미지를 로컬 빌드하므로 digest 는
   갈리고, 그것이 정상이다.
3. **컨테이너 산출물을 직접 전달하지 않는다.** 이미지 save/load 전송은 영구 금지이고, 전달 단위는
   빌드킷과 **레시피**다. 서브는 받은 레시피로 자기 빌드를 돌린다.
4. **서브의 런타임 스킬은 꺼진다.** 서브의 tool_plane 은 비어 있다 — 탐색·벤치·발행은 메인 평면의
   일이다. 이 사실의 **정본은 `node_role_contract.py` 의 manifest 파생값**이고 여기서는 *왜 그런가*만
   말한다: Ray 워커는 판단 주체가 아니라 집단 연산 안의 위치이기 때문이다.
5. **Ray role 은 최대한 평등하게 둔다.** head/worker 는 제어 평면의 비대칭일 뿐이고, 연산 부담과
   메모리 예산에서는 평등을 지향한다. 예산 파생이 노드 역할의 함수여야 하는 자리에 상수가 박혀
   있다면(같은 `OVERHEAD_MIB` 를 두 노드가 공유하는 식) 그 비대칭이 **의도된 것인지** 먼저 묻는다.

## 캠페인 배정 — 셀은 클러스터 단위다

- 한 셀 = 두 노드가 함께 도는 분산 서빙 1회다. 노드별로 셀을 나눠 동시에 돌리지 않는다 — `assignments`
  에는 메인만 등장하고 서브는 그 셀의 일부로 참여한다. 공통층 `workflow.md` §배정 계층이 말하는
  "서로 다른 노드의 리스트는 동시에 돈다"는 이 토폴로지에서 **적용되지 않는다**.
- 착수 순서에 서브 지시서 선행 규칙이 없다. 서브는 독립 셀을 받지 않기 때문이다.
- 감독은 상주가 아니라 한 걸음이다(`relay.py --supervise-step`) — 절차 정본은 공통층이다.
- 벤치(GuideLLM)는 API 서버가 있는 **메인에만** 뜬다(`--network host` 로 `localhost:$PORT` 에 붙는다).
  예산 파생에서 이 비대칭을 지운 상수는 결함이다.

## 서브에 여는 것 / 열지 않는 것

| | 멀티에서 |
|---|---|
| 빌드킷 배달 평면 | **active** |
| 에이전트 환경 오버레이 | active |
| 서브 런타임 스킬(explorer·benchmarker·hint-publisher) | **off** — 정본은 `node_role_contract` 파생값 |
| 서브의 자율 빌드 판단 | ✗ — 레시피를 따른다 |
| 서브 → 메인 상향 | 문서기반 회수만(공통층) |
