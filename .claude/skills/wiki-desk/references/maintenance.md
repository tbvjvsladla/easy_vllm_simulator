# 질의·증분 입고·정합성 유지 (TS판)

## 작업별 최소 범위
| 작업 | 범위 | 자동으로 추가하지 않을 것 |
|---|---|---|
| 질의 | 색인 후보 → 근거 구간 원문 | 전체 재검토·sync·제품 재실행 |
| 입고(`sync`) | 계약 source 범위와 기존 카드 대조 | 원문 복사·합의 밖 경로 확장 |
| `check` | bundle 전체 Markdown + 카드↔원문 대응 | 원문 수정·권위 재정의 |

## 색인 캐시
- `<wiki_dir>/<cache_dir>/`의 역색인은 카드·원문에서 파생된다. 원문 sha256이 바뀐 문서만 다시 색인하며, 질의 때 자동으로 갱신된다. 카드가 아니므로 `--apply` 대상이 아니다.
- 캐시를 지워도 지식 손실은 없다(다음 질의에서 재구축). 소유 기록 `receipt.json`은 캐시 밖(추적 대상)에 있어 영향이 없다. 캐시가 손상되면 질의가 전량 재색인하고 `index_cache_reset`에 사유를 보고한다.

## 입고 시점과 범위
- 설치 프로젝트의 작업 절차가 정한 시점에, 그 작업에서 생성·변경된 문서 전체를 `sync --apply`로 입고한다. hook·watcher는 없다.
- `sync`는 계약 범위 전체를 대조해 증분을 계획한다. 계획에 예상 밖 변경이 있으면 적용하지 않고 원인을 확인한다.

## 원문 삭제·이동
- 기본 `sync`는 카드가 있는데 원문이 사라진 경우(고아) 적용을 거부한다.
- 사실을 확인한 뒤 지정 경로만 조정한다:
  - `sync --accept-removed docs/x.md` — 카드를 archived로 보존 이동
  - `sync --relocate docs/old.md=docs/new.md` — 옛 카드를 archive로 보존하고 log에 이동을 기록. 새 경로 카드는 새로 만들어지며 필드 이력은 넘어가지 않는다
- 원문 파일 자체를 지우거나 옮기는 명령이 아니다. 나머지 고아 검사를 끄지 않는다.

## stale·누락·고아
| 상태 | 뜻 | 조치 |
|---|---|---|
| 누락 | 원문은 있는데 카드 없음 | 다음 입고에서 생성 |
| stale | 카드의 `source_sha256` ≠ 현재 원문(원 바이트 해시) | 다음 입고에서 갱신, query 출력 최상위 `stale` 목록에 경로 표시 |
| 사람 키 | 카드 frontmatter에 사람이 키를 도구 출력 형식 그대로 더함(주석·다른 따옴표 없음) | 원문이 바뀔 때만 sync가 갱신하며 키를 도구 키 뒤에 다시 씀. remove는 보존하고 소유 기록을 남김 |
| 재확인 | 사람 확인 `verified`가 있는 카드의 원문이 바뀜 | sync가 카드를 그대로 두고 `reverify`로 보고(check는 stale). 해소: `verified`를 보관·삭제 → `sync --apply` → 새 원문 확인 후 `verified` 재기록 |
| 보호 | 그 밖에 사람이 고친 카드(본문·카드 키) | sync가 덮어쓰지 않고 `protected`로 보고 — 수정분을 옮긴 뒤 카드를 지우고 `sync --apply`로 재생성 |
| invalid | 카드 형식 오류 | check는 `card.invalid`, query는 `invalid_cards`로 보고하고 계속 |
| 고아 | 카드는 있는데 원문 없음 | accept-removed / relocate로 명시 조정 |

## 실패 처리
실패 명령·exit code·진단·부분 상태·롤백 범위를 그대로 보고한다. 같은 입력을 근거 없이 재시도하지 않는다. 심링크·루트 탈출·의존성 부재는 권한 완화나 자동 설치로 우회하지 않는다. 파일 단위 원자적 교체와 예외 시 롤백은 OS/프로세스 강제 종료까지 보장하는 원자성이 아니다.
