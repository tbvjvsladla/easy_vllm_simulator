# docs/request/ — 사람 수행지시서 (7번째 산문 문서형)

> 이 파일은 폴더의 목적을 설명하는 **추적되는 스켈레톤**이다. 실제 지시서는 gitignored 다.
> 규칙 정본: `.claude/rules/docs.md` §명명 SSOT · §`request/` · §보관·전파 matrix.

## 이 폴더에 무엇을 발행하나

**에이전트의 실행 평면 밖에서만 완수되는 과업**을 사람에게 위임하는 문서를 발행한다.
에이전트가 못 하는 일에는 두 종류가 있고, 이 폴더는 **뒤쪽**만 다룬다.

| 구분 | 예 | 처리 |
|---|---|---|
| 하면 안 되는 일 (권한·안전 경계) | 무단 다운로드, 서빙 임의 재기동 | 승인 요청(HITL). request 아님 |
| **할 수 없는 일 (물리적·환경적 불가)** | 다른 아키텍처 머신에서의 실행, 물리 작업(케이블·전원), sudo 설치, 외부 계정 권한이 필요한 절차 | **request 발행** |

plan 이 "우리가 무엇을 할 것인가"라면, request 는 **"당신이 무엇을 어떻게 해야 하는가"**다.
지시받는 사람이 이 문서 하나만 들고 다른 머신 앞에 앉아도 과업이 완수돼야 한다.

## 명명

`docs/request/request_<YYMMDDHH>[_MM_SS]_<주제>.md` — plan/devlog/testlog 와 같은 날짜 규약이다.
report 처럼 "최신본 갱신"하지 않는다. 같은 과업을 다시 지시하면 **새 문서를 낸다**(지시는 시점에
묶인 사실이고, 수행자가 들고 간 판본이 무엇이었는지가 나중에 문제 원인을 가른다).

## 필수 구성 6가지

1. **전제·준비물** — 하드웨어, 네트워크 도달성, 필요한 권한(sudo 여부), 디스크·시간 예산
2. **단계별 명령** — 복사해 붙여넣을 수 있는 형태. 도구는 **버전을 핀**한다(커밋 SHA·태그)
3. **성공 판정 기준** — 각 단계마다 "무엇이 보이면 다음으로 넘어가는가". 이게 없으면 수행자가
   실패를 성공으로 오인한다
4. **실패 시 분기** — 알려진 실패 모드와 그 처방. 우리가 이미 밟은 지뢰는 반드시 적는다
5. **회수물 목록** — 수행 후 에이전트에게 돌려줄 파일. **이게 없으면 지시는 미완결이다**
6. **예상 소요·비용** — 사람이 일정을 잡을 수 있어야 한다

## 금지

- **추측 명령** — 실행해 보지 않은 절차를 검증된 것처럼 적지 않는다. 미검증분은 "미검증"이라 표기한다.
- **환경 구체값 하드코딩** — 주소·경로·호스트명은 플레이스홀더로 두고 **획득 방법**을 적는다.
  (PII 3종 스캔 대상이기도 하다: `private-ipv4`·`email`·`spark-host`)
- **회수물 없는 지시** — 결과가 에이전트로 돌아오지 못하면 과업이 닫히지 않는다.

## evidence chain 과의 관계

request 는 **chain 밖**이다. 판정(testlog)도 계측(benchmark)도 아니므로
`evidence_publisher` 의 scaffold/completion 게이트를 타지 않는다.
수행자가 회수물을 가져오면 **그때** testlog(판정)·devlog(서사)로 chain 에 편입한다.

```
plan (우리 계획)  →  request (사람 위임)  →  [사람 수행]  →  회수물  →  testlog/devlog
```

## 추적

**비추적이다.** 운영자 환경의 절차라 배포 대상이 아니며 `.gitignore` 의 `docs/*/*` 가 무시한다.
이 `example.md` 만 `!docs/*/example.md` 예외로 추적된다 — 그래야 fresh clone 에도 폴더가 실린다.
서브노드에는 렌더하지 않는다(메인 전용).
