# testlog/ — 검증 로그 (검증 **결과·증거**)

> 이 `example.md`는 **추적되는 스켈레톤**이다(폴더 구조 + 작성 규칙 배포용). 실제 검증 로그는
> 이 폴더에 추가하되 **git 추적 대상이 아니다**(gitignore — 브랜치 간 persist·통합). 작성 규칙 정본: `.claude/rules/docs.md`.

## 역할
- 빌드/스모크/실험의 **증거와 판정**("동작을 확인했나").
- 담는 것: 목적, 전제(resolve값), 실행 커맨드, 관측(로그·수치), **합격/실패 판정**, 실패 시 근본원인.
- 컨테이너 변경은 스모크 통과(testlog 증거) 전 done 금지(검증 게이트).

## 환경 스냅샷 (필수 — 미래 세션이 판정 시점을 복원 가능해야 함)
- 이미지 태그(예 `easy-vllm:<vllm>-cu<cuda>-<arch>-source`) · 핵심 env 실값 · 판정 시점 config.
- trial 스윕이면 per-trial config 사본을 simlog run 디렉토리에 적재하고 본문엔 run 경로 인용
  ("S2가 정확히 어떤 yaml/플래그였나"가 복원 불가하면 미완성 testlog).

## 판정 위생 (앵커링 방지 — 정본: docs.md §3)
- 단정 판정엔 **유효맥락 한정자** 병기: "비가용[맥락: <이미지/포크 SHA>·<HW>·<일자> 시점]".
- 이 문서의 판정을 후속 문서가 뒤집으면, **뒤집는 문서를 쓰는 에이전트**가 이 문서 헤더에 배너 추가:
  `> ⚠ SUPERSEDED-IN-PART by `docs/testlog/<후속 문서>.md` — <뒤집힌 판정 1줄>`
- 후속 확인 마커는 체크박스: `- [ ] 후속: ...` → 닫힐 때 `- [x] 후속: ... → <해소 문서 경로>`.

## 파일명 규칙
```
docs/testlog/testlog_<YYYYMMDDHH>_<seq>_<주제>.md
```
- `YYYYMMDDHH`: 작성 일시 절대표기 (예 `2026060814` = 2026-06-08 14시). 상대날짜 금지.
- `seq`: 같은 일시·같은 type 내 일련번호(1부터).
- `주제`: 한국어, 밑줄(`_`) 구분, 버전·대상 포함 권장.
- 예: `testlog_2026060814_1_멀티노드_소스빌드_vLLM0.22.1_검증.md`
