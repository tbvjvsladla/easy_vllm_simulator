# 서고 하나 · 사서 N명 — 재발급·색인·동시성·A2A 부하 정량 보고 (2026-10-19)

> 대상: easy-vllm-simulator 배포자·운영자. 무엇이 바뀌었는지는 2026-10-19 개정(서브 wiki-desk 가 메인 `__llm-wiki` 에
> ssh 강제명령 게이트웨이로 직접 닿는다 · 옛 A2A 서고 교환 폐지)을 전제로 한다. 이 보고서는 그 개정이 **실제로 서는지**와
> **무엇을 줄였는지**를 메인 1대 + 서브 1대(GB10 aarch64) 실측으로 답한다. 수치는 모두 측정값이며 출처를 열마다 밝힌다.

## 한 줄 결론

- 메인·서브 manifest 를 처음부터 다시 발급해도 접근점은 다시 선다. 단 **순서**(병합 뒤 접근점 재발급)와 **병합 규칙**(emit 이 가진 키만 · 중첩 키 포함)을 지켜야 한다.
- 서고 1개에 사서 4명이 동시에 입고·질의해도 유실·중복·중간상태가 0이었다. 강제 kill 은 48회였다. 잠금을 끄면 같은 시험이 3/3 실패한다.
- A2A 평면 부하는 줄었다: 질문 1묶음당 A2A 세션 2→1, relay 왕복 1→0, A2A 본문 바이트 −87%. LLM 비용은 같은 자릿수다(출력 토큰 −19% · 캐시 생성 +25%). 줄어든 일은 A2A 밖 게이트웨이 ssh 로 옮겨 갔다(1묶음당 14.3회). 인용 품질은 새 정책이 높았다(직접 답 0/9 → 6/9).

## 1. 재발급 — 메인·서브 manifest 를 처음부터 다시 낼 때

양 토폴로지에서 아래 순서를 실제로 돌렸다(정본 절차: `terraforming_node/references/orchestration/grounding_exchange.md` §재발급).

1. 메인 스캔: `scan_node.py --emit-manifest --emit-sub-manifest`. multi 는 `--peer-ip`·성능 실측이 필수다.
2. 메인 manifest 병합(HITL): emit 블록이 가진 키만 바꾼다.
3. 접근점 회수 → 재발급: `library_access.py`.
4. 서브 배달: `render_sub_env.py` + `sync_to_sub.sh`.
5. 서브 확인: 원격 `read` = 메인 로컬 `read`(sha256 일치) · 입고 → 질의 적중.

| 단계 | single | multi |
|---|---|---|
| 스캔 | 1.7 s · exit 0 | 첫 시도 `pending-perf` 거부(정상) → RoCE 포트별 109.2·109.2 Gb/s 실측 주입 → exit 0 |
| 병합 | 스캔 밖 9키 보존 | 스캔 밖 6키 + 중첩 1키 보존 |
| 접근점 재발급 | 1.0 s | 동급 |
| 회수 창의 서브 표시 | status·query·sync 모두 구조화된 미도달 + exit 4 | 같음 |
| 재발급 뒤 | 원격 read 바이트 동일 · 입고 즉시 질의 1위 | 같음 · 회수 창에 쓴 문서가 다음 입고로 따라잡힘 |

실측이 드러낸 이음매 네 가지(모두 절차 문서에 반영):

| # | 이음매 | 무엇이 깨지나 | 처방 |
|---|---|---|---|
| 1 | emit 블록에 `library` 가 없다 | 통째로 덮으면 서고 접근자가 사라진다 | emit 이 가진 키만 바꾼다 |
| 2 | single 메인 host 가 손으로 적은 주소에서 스캔 값(hostname)으로 바뀐다 | 스캔 시점에 발급된 서브 접근자는 옛 주소를 든다 | 접근점 재발급은 **병합 뒤** |
| 3 | 사람이 덧붙인 중첩 키(multi `interconnect.nccl_transport`)가 emit 에 없다 | 최상위 키째 바꾸면 NCCL 전송이 socket 으로 돌아간다 | 중첩 키도 emit 이 가진 것만 |
| 4 | `--peer-ssh` 의 host 부분이 서브 hostname 이 된다 | 주소를 넘기면 hostname 자리에 주소가 들어간다 | 관리 hostname 을 넘긴다 |

## 2. 사서 N명 실색인

사서 4명: 메인(로컬) · 서브(실노드) · 가상 2명. 가상 사서는 서브 호스트에 node_id 가 다른 별도 키를 발급한 것이다(`library_access.py --host-of`). 사서마다 표지 문서 5건을 입고한 뒤 서로의 표지를 질의했다.

| | single | multi |
|---|---|---|
| 소유자별 표지 카드 | 5/5 ×4 | 5/5 ×4 |
| 교차 적중(표지 + 마지막 반복 토큰) | 메인 시점 8/8 · 서브 시점 24/24 | 8/8 · 24/24 |
| 서고 `check` | 원문 627 = 카드 627 | 663 = 663 |

## 3. 동시성 — 사서 4명 동시 쓰기 + 강제 kill

메인은 입고와 질의를 번갈아 돌렸고, 입고 7회마다 kill 을 넣었다. 그동안 서브 측 사서 3명이 각 25회 원격 입고·질의를 동시에 돌렸다. 두 부하는 시간상 완전히 겹쳤다.

| 지표 | single | multi |
|---|---|---|
| 메인 입고(정상 / kill) | 141 / 23 | 156 / 25 |
| 원격 입고 · 원격 질의 | 78/78 · 75/75 성공 | 78/78 · 75/75 |
| 메인 질의 | 164/164 JSON | 180/180 |
| 유실(마지막 반복 미적중) · 중복 카드 · 잔재 | 0 · 0 · 0 | 0 · 0 · 0 |
| 같은 요청 재전송 | 재생(no-op) 3/3 | 3/3 |
| 같은 요청 id · 다른 내용 | 충돌 거부 3/3 | 3/3 |
| 메인 입고 p50 / p95 | 1.7 / 2.7 s | 0.6 / 2.5 s |
| 원격 입고 p50 / p95 | 7.0 / 8.2–9.2 s | 7.5–8.0 / 8.3–9.2 s |
| 원격 질의 p50 / p95 | 1.95 / 2.0–3.3 s | 1.97 / 2.1–2.4 s |

- 음성대조: 같은 동시 입고 시험을 잠금 없이 돌리면 3/3 실패한다(저널 rename 실패 · 롤백 불완전 · 읽기 재확인 불일치). 잠금을 켜면 통과한다. 시험이 실제 경합을 잡는다는 증거다.
- 원격 입고 7–9 s 의 대부분은 반입(rsync 2회)과 잠금 대기다. 서고가 하나라서 쓰기는 직렬화된다. 이것이 동시성 규정(배타 쓰기 잠금)의 비용이다.

## 4. A2A 평면 부하 — 옛 정책 대 새 정책

같은 질문 3개("근거를 찾아 인용하라")를 서브에 맡겨 팔마다 3회 돌렸다. A팔은 옛 코드(옛 relay·옛 사서·옛 서고 재구축)로 돌렸고, 서브에는 옛 규약 원문을 과업 본문으로 주었다. B팔은 현 정책이다.

| 지표(1묶음 평균) | A 옛 정책 | B 새 정책 | 변화 | 출처 |
|---|---|---|---|---|
| A2A 세션 | 2 | 1 | −50% | relay 원장 |
| relay 왕복(input-required → 재개) | 1 | 0 | −1 | relay 원장 |
| 메인 relay 호출 | 2 | 1 | −50% | relay 원장 |
| A2A 위임 본문 | 15.5 KB | 2.0 KB | −87% | 위임 요청 원문 |
| A2A 리포트 | 2.8 KB | 1.3 KB | −54% | 리포트 원문 |
| LLM API 시간 | 49.1 s | 29.0 s | −41% | relay 원장 |
| 서브 턴 수 | 7.3 | 12.0 | +64% | relay 원장 |
| 출력 토큰 | 4,819 | 3,902 | −19% | 서브 세션 기록 |
| 캐시 생성 토큰 | 43,657 | 54,700 | +25% | 서브 세션 기록 |
| 캐시 읽기 토큰 | 320,552 | 307,624 | −4% | 서브 세션 기록 |
| 끝-끝(재개 즉시 자동 · 최선값) | 44.2 s | 42.6 s | −4% | 구동기 벽시계 |
| 게이트웨이 ssh(A2A 밖) | 0 | 14.3 | +14.3 | sshd 로그(서브 키 지문) |
| 직접 답한 질문 | 0/3 | 2/3 | +2 | 결과 문서 판독 |

- **운영 이력**: 옛 교환 7건 중 완결 5건의 요청→인증 간격은 61·385·448·452·1209 s(중앙값 448 s)였고, 2건은 끝나지 못했다. 옛 정책에서는 재개가 감독 스텝이나 사람에게 걸려 있었다. 위 A 의 44 s 는 재개를 기계가 즉시 건 최선값이다. 새 정책에는 그 대기가 구조적으로 없다(질문이 세션 안에서 끝난다).
- **줄어든 것**: A2A 세션·왕복·본문 바이트, 메인 relay 개입, 사람·감독이 재개를 걸어야 하는 지점.
- **줄지 않은 것**: LLM 토큰은 같은 자릿수다. 서브가 직접 질의·열람하므로 턴 수와 캐시 생성은 늘었다.
- **옮겨 간 것**: 1묶음당 게이트웨이 ssh 14.3회. A2A 평면이 아니라 사서 명령 하나만 여는 별도 평면이다.
- **품질**: 옛 경로는 질문 3개를 한 질의로 묶어 한 번 반출하고, 서브는 되묻지 못한다. 새 경로는 서브가 질의를 다시 고칠 수 있었다.

## 5. 한계

- 서브는 물리 1대다. N=4 중 둘은 같은 호스트의 가상 사서다(키·node_id·미러는 별개). 네트워크 경로는 사서 3명이 공유했다.
- A/B 는 single 에서만 쟀다(A2A 위임이 본업인 토폴로지 · 서고 접근 코드는 토폴로지와 무관). 반복은 팔마다 3회다.
- A팔의 서브 측 옛 규약은 옛 오버레이 배달 대신 과업 본문으로 주었다. 4자일치 가드가 detached worktree 배달을 막았고, 우회하지 않았다. relay·사서·스키마는 옛 코드 그대로다.
- 토큰은 서브 세션 기록을 서브가 합산해 A2A 로 회수한 값이다(relay 원장은 토큰을 남기지 않는다).
- 판정 증거와 원시값은 비배포 평면(testlog·simlog)에 있다.
