# 캠페인이 이제 노드를 동시에 돌린다 — 같은 측정, 3배 빠른 벽시계

> 분류: harness · 발행: 2026-09-08 · 실행: 2026-09-08 · 대상: `campaigns/` 아티팩트 체인과 메인↔서브 릴레이
> 검증 방식: 직전 캠페인(Qwen3-4B KV 양자화 4군)을 **같은 입력·같은 통제변인으로 전체 재수행**해
> 측정이 재현되는지와 벽시계가 줄는지를 함께 본다.

## 요약

여러 노드가 나눠 도는 캠페인이 실제로는 **순차로** 돌고 있었다. 메인이 자기 셀 둘을 끝낸 뒤에야
서브 지시서가 나갔고, 그 사이에 사람 승인 대기가 70분 들어갔다. 원인은 하네스 성능이 아니라
**선언이 노드 분할을 표현하지 못한 것**이었다 — 실행 목록이 평면 배열이라 "메인이 A·B, 서브가 C·D"를
적을 자리가 없었고, 적을 수 없는 것은 배선될 수 없었다.

선언을 노드별 배정으로 바꾸고, 서브가 지시서 하나로 착수하게 하고, 진행을 읽는 허가된 자리를
만들었다. 같은 4개 군을 다시 재니 **KV 용량은 네 군 모두 완전히 일치**했고 처리량 드리프트는
0.25% 이내였으며, 벽시계는 **7시간 27분 → 2시간 31분**이 됐다.

## 무엇이 달라졌나

| | 직전 실행 | 재수행 |
|---|---|---|
| 서브 착수 | 메인 2셀 완료 **뒤** | 메인 첫 착수 **71초 전** |
| 서브가 착수에 필요한 것 | 메인의 빌드 산출물 배달 + 승인 대기 | **지시서 하나**(자기 몫만 담긴 파생 선언) |
| 진행 관측 | 원격 셸로 직접 들여다봄(29회) | 서브가 발행한 진행 요약 파일 1개를 회수 |
| 서브 진행 기록 | 캠페인이 끝난 뒤 메인이 한 번에 대신 작성 | 서브가 단계마다 스스로 기록 → 회수 시 자동 편입 |
| 위임 단위 | 셀 두 개를 한 문맥에 묶음 → 시간 상한에서 2/2 절단 | 셀 하나 = 문맥 하나 → **상한 도달 0회** |
| 벤치 벽시계 | 7시간 27분 | **2시간 31분** |

## 측정이 재현됐다 — 그래서 계약 변경이 결과를 흔들지 않았다

같은 11.0 GiB KV 예산에서 dtype 별 토큰 용량비가 곧 실측 압축비다.

| 실험군 | KV 풀(토큰) | 압축비 | 스트림당 decode tok/s | 직전 값 | 드리프트 |
|---|---|---|---|---|---|
| 무양자화(BF16) | 80,096 | 1.00× | 19.13 | 19.12 | +0.05% |
| FP8 | 160,192 | 2.00× | 20.25 | 20.20 | +0.25% |
| TurboQuant 4bit | 232,992 | 2.91× | 18.56 | 18.56 | 0.00% |
| TurboQuant 3bit | 277,920 | 3.47× | 17.62 | 17.58 | +0.23% |

- **네 군의 KV 토큰 용량이 직전과 완전히 일치**한다. 측정 대상은 그대로 두고 운영 방식만 바꿨다는 뜻이다.
- 성능 수치 자체의 해석은 별도 리포트 `perf_26090801_qwen3_4b_kv양자화_대조군_24gb.md` 를 본다.
  이 문서의 주제는 그 수치가 **어떻게 얻어졌는가**다.
- 조건: Qwen3-4B · vLLM 0.26.0 소스빌드 · GuideLLM closed-loop · 입력 8192 / 출력 1024 / 32요청 ·
  KV 절대 클램프 11.0 GiB 4군 동일. 측정 HW는 통합메모리 노드이므로 **절대 처리량은 참고치**이고
  군 간 상대비가 주 결과다.

## 이 저장소를 쓰는 사람에게 달라지는 것

- **캠페인 선언이 노드별 배정을 갖는다.** 각 노드의 셀 목록과, 셀이 끝난 뒤의 전이(자동 진행 ·
  사람에게 묻고 대기 · 서빙 유지)를 선언에 적는다. 서로 다른 노드의 목록은 동시에 돈다.
- **서브는 지시서만으로 착수한다.** 메인의 해소 결과를 받지 않고 자기 하드웨어에서 스스로 해소한다.
  참고 자료가 필요하면 "무엇을 찾는지"만 올리고, 메인 사서가 답을 다음 턴에 실어 보낸다.
  못 찾으면 그 사실을 기록하고 그대로 진행한다 — 자료 없음이 작업을 막지는 않는다.
- **진행을 읽는 자리가 하나로 정해졌다.** 각 노드가 단계마다 갱신하는 진행 요약 파일이고,
  메인은 그 파일 밖으로 상대 노드를 들여다보지 않는다.
- **서빙·트라이얼 진입에 참조 게이트가 생겼다.** 캠페인이 자기 통제변인에서 뽑은 질의로 내부
  문서고에 먼저 묻고, 그 기록 없이는 컨테이너를 띄우지 않는다. 문서고가 "없다"고 답하는 것은
  통과이고, 답을 거절한 경우만 막는다. 발행이 끝나면 그 문서가 문서고에 자동으로 들어간다.
- **캠페인 밖 평시 서빙은 영향이 없다.** 위 게이트들은 활성 캠페인이 있을 때만 동작한다.

## 이번 실행이 드러낸 것

계약을 바꾸자마자 **자체 검사가 전부 통과하는 상태에서** 배선 결함 7건이 라이브에서 나왔다.
가장 무거운 것은 두 스크립트가 같은 개념에 다른 낱말을 쓰고 있던 자리다 — 분류기가 낸 결과값을
기록기가 몰라서, 측정은 성립했는데 **그 셀의 기록이 통째로 남지 않았다**. 각 스크립트는 따로
시험했고 그 경계는 시험하지 않았다. 처방은 값 하나를 더하는 것이 아니라, 두 어휘가 갈라지면
커밋 전에 실패하게 만드는 것이었다.

두 건은 **서브 노드가 자기 환경에서 도구를 돌려서** 찾았다: 자체 검사 픽스처가 메인에만 있는
파일을 참조하던 것과, 정리 게이트가 릴레이 기록을 갖지 않는 노드에서 영원히 열리지 않던 것이다.
둘 다 메인에서는 영원히 초록이었을 결함이다.

## 한계와 미검증

- **원격 셸 직접 관측 1건**이 남았다. 캠페인 착수 전 도달 확인으로 열었고, 신설한 감사가 그것을
  잡았다. 대체 경로(문서 회수 스크립트의 예행 모드)를 문서에 명시했다.
- **시간 상한으로 죽은 세션의 이어받기**는 이번 실행에서 그 상황이 발생하지 않아 검증되지 않았다.
- **서브의 자료 요청 왕복**은 서브가 질문을 올리지 않아 실동 확인이 없다(배선 검사만 통과).
- 메인 두 군의 **동시성 4 구간은 측정 파싱 실패로 절삭**됐다. 비교 축인 동시성 1은 온전하며,
  절삭 사실이 기록에 남는다.
