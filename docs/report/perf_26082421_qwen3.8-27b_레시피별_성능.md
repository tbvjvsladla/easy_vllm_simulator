> ⚠ **multi 2종은 `THERMAL_LIMIT_LITE_ONLY`** — GB10 SoC 95℃ 초과(수동냉각)로 warm/full 벤치가
> docker_kill 되어 **lite cold 단일 요청(TTFT·output_throughput)** 만 측정. multi 14.54/8.40 t/s 는
> single 의 full-bench gen t/s 와 **like-with-like 비교 불가**다(1프롬프트 cold vs 16프롬프트 warm).

## 핵심 인사이트

1. **MTP 가 천장을 넘는 유일한 serve-plane 레버** (single 262k): spec-off **4.59** → n=1 **7.47** →
   n=2 **9.26** → n=3 **9.99** = **2.18×**. 대가로 TTFT 가 오른다(spec-off 927ms → n=3 1158ms).
2. **fp8 가중치가 두 번째 레버** (single 1M): bf16 가중치 대비 **1.73×** (10.81 → 18.69).
   fp8 KV 는 1M 티어의 **유일한 관문**(bf16 KV 면 65.47 GiB 필요로 구조적 불가 → fp8 이 1,058,084 tok 확보).
3. **multi TP=2 에서 두 레버 재현** (같은 1프롬프트 cold 비교): 8.40 → 14.54 = **+73%**.
   fp8w per-rank 14.46 GiB (single 28.89 의 TP=2 절반) 샤딩 정합.
4. **컨텍스트 확장 정본은 `--hf-overrides`**(rope YaRN factor 4.0/2.0) + `VLLM_ALLOW_LONG_MAX_MODEL_LEN=1`.
   `--rope-scaling` 은 이 모델에서 침묵 no-op(플래그 자체가 없다).
5. **전 항목 REFUTE vs E=26.0** — floor 22.1 미달. 발행 자격은 성능이 아니라 **서빙 성립 ∧ 유효 측정**
   (`authority=explore`). 물리 천장(≈5 t/s)이 낮은 dense 모델이라 구조적으로 그렇다.
