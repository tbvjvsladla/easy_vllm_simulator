```
2) 파이썬이 아닌 텍스트를 patch 로 stamp/verify → RC=0 (통과)   ← compile/ast.parse 0줄
```

실제로 집행하는 것은 `RUNTIME_PATCH_NO_CARRY_FORWARD`가 아니라 **"stamp 이후 바이트가 안 바뀌었다"**(tamper seal)다.

> ⚠ **그냥 지우면 안 된다.** ⑦-c에서 사용자 전제가 반증됐으므로, 지운 자리에는 **패치가 실제로 발화했는지를 serve 로그에서 확인하는 fail-loud 검사**가 들어가야 한다. `workflow.md`가 이미 *"런타임 슬롯은 '먹었는지'를 반드시 로그로 실증하라"*고 요구하는데 **구현이 없다.**

## §4. 올바른 절단선 — git 중복층 vs git 맹점층

같은 `sha256`이라도 **대상이 추적물인지**에 따라 성질이 정반대다. 이 선이 삭제의 유일하게 방어 가능한 기준이다.

### 4.1 git 중복층 (git이 이미 주소화 → 삭제 가능)

| `tracked_index.json` entries 98 | `git ls-files -s` blob SHA-1의 **문자 그대로의 사본**(98/98 일치) |
| `tracked_index.base_tree_sha1` | 형식만 검사 — 값이 stale인데 통과 |

### 4.3 백업 프로세스 — 코드 안에는 중복이 없다

`.claude/` 전체에서 **git 추적물을 그림자 복제하는 `.bak`은 0건**이다(`.bak` 생성 지점 grep 0건). 남아 있는 copy-backup은 전부 git이 못 track하는 것을 덮는다:

| 메커니즘 | 대상 | 판정 |
|---|---|---|
| 서브 dirty autosave `[improve]` 커밋 | 서브 워킹트리 | **KEEP** — `.bak`이 아니라 **git 그 자체** |

### 4.4 실제 백업 중복은 코드가 아니라 `seed/`에 있다 — 다만 판정은 반전된다

사용자가 물은 *"git 커밋 히스토리만으로 충분한데 존재하는 불필요한 백업"*에 가장 정확히 해당하는 것은 스크립트 내부 백업이 아니라 **`seed/` 아래의 수동 전체 사본**이다. 실측:

| 항목 | 크기 | 파일 수 | 내용 |
|---|---:|---:|---|
| `seed/easy-vllm-simulator 백업` | 51 MB | 1,150 | **저장소 전체 사본**(`.git` 400파일 포함 · HEAD `d9fbdfb`) + `docs/` 454 + `envs/` 1 |

`seed/`는 `.gitignore:230`으로 비추적이므로 배포에는 실리지 않는다. 그리고 **추적 파일 내용에 관한 한 이 사본은 순수 중복**이다 — `.claude/`·`CLAUDE.md`는 라이브 저장소의 커밋 히스토리로 완전 복구된다.

**그런데 태그를 세면 판정이 뒤집힌다:**

```

백업 저장소 태그 수   : 63
백업 raw 태그 본문     : 63    (tags.json 에 roundtrip_verified 필드 존재)
```

직전 커밋 `5d096ce`("태그 정리 후 낡은 데이터 회수 — legacy 핀 제거")가 태그를 대량 정리했고, 그 **직전에 63건을 검증된 형태로 내보낸 것**이 이 백업이다. 즉 이것은 "git이 이미 하는 일의 중복"이 아니라, **git이 곧 잃게 될 데이터를 파괴적 연산 직전에 건져낸 회수물**이다 — 백업의 정당한 용법이다. 여기에 `docs/` 454개 비추적 작업문서와 `envs/` 실값이 더해진다.

| 대상 | 판정 |
|---|---|
| 백업 사본의 **추적 파일 내용** | **중복** — 라이브 git 히스토리로 복구 가능 |
| 백업 사본의 **태그 62건** | **중복 아님** — 라이브에 없다. origin 잔존 여부는 오프라인이라 미확인(**결정 필요**) |
| 백업 사본의 `docs/` 454 · `envs/` | **중복 아님** — 비추적, 유일 사본 |
| `hint_tags_backup_26090108` | **중복 아님** — 위 태그 62건의 정본 회수물 |

> **권고**: 저장소 전체 사본(51 MB)은 `origin`에 태그가 남아 있음을 확인하는 즉시 **태그 부분의 중복성이 확정**되고, 그러면 남길 가치가 있는 것은 `docs/`·`envs/` 뿐이다. 그 확인 없이 지우면 태그 62건이 영구 소실된다. **먼저 `git ls-remote --tags origin`으로 확인할 것.**

> **따라서 "과도하게 적용되어 있다"는 문제 제기는 확정된다.** 이 장치는 위에서 지시된 것이 아니라 **아래에서 자랐다**. 동시에 이것은 좋은 소식이기도 하다 — **삭제에 필요한 헌법 개정이 거의 없다.** 정책 경계 1줄과 last-good 문구를 손보면 끝이며, 계획이 제안한 40줄짜리 「행동규칙 0」 블록은 **제거하는 코드보다 늘어나는 헌법이 더 많다**.

부가 사실: `registry.yaml`의 **13개 정책 전부가 `status: candidate` · `last_reproduced: null`**이다. end-to-end 재현된 정책이 하나도 없다.

### 6.2 제안된 「행동규칙 0」은 채택하지 말 것 — 네 가지 이유

1. **하네스가 실행되지 않는다**(§1.4). 음성대조 5종도 함께 무효다.
2. **저장소 자신의 판정 규율과 충돌한다.** `workflow.md`의 4종 안티패턴 판정표는 2026-08-14 사용자 결정으로 *"양태는 `금지`가 아니라 `자제`"*이고, *"패턴 이름만으로 하는 기각은 무효이며 결함 칸의 어느 조건에 걸리는지를 지목해야 한다"*고 못박았다. 「해시라는 이름이면 금지」는 정확히 그 무효한 기각 형태다.
3. **금지 범위가 과잉이다.** `digest`라는 단어를 금지하면 OCI/레지스트리 **이미지 digest**(정당한 도메인 개념)와 §4.2의 git 맹점층 검증이 함께 걸린다. 실제로 이 감사가 확인한 KEEP 항목 9종이 전부 위반이 된다.
4. **진짜 위험을 못 막는다.** 이 저장소를 실제로 다치게 한 것은 해시가 **있어서**가 아니라 §5의 fail-open과 §4.1의 손저작 미러 **때문**이었다.

**대안 문구(권고)** — 금지가 아니라 판정 기준을 헌법에 둔다:

> 무결성 해시는 **git이 그 바이트를 들고 있지 않은 대상에만** 둔다. 추적물의 digest를 별도 파일에 다시 적지 않는다 — git이 이미 content-addressed다. 검증을 추가할 때는 **누가 그것을 실행하는가**를 먼저 적는다(실행자가 없으면 안전장치가 아니라 장식이다).

이 세 문장은 §4의 절단선·§5의 배선 결함·헌법의 「처방 주체 선기재」 불변식을 동시에 담고, 유지 대상 9종을 잘못 걸지 않는다.

| 사실 | `install_node_blackbox.sh` · `verify_node_blackbox.sh` · `purge_host_safety.sh` 세 파일에 대한 감사는 **정적 판독까지**다(실행에 하드웨어·root 필요). 이 영역에서 **에이전트 오탐 1건**이 나왔고 재검증으로 철회했다(§5 B12 주). 나머지 항목은 재확인됐다 |
| 갈림 | 세 파일만 별도로 재감사할 것인가, 아니면 §5 Tier 0 수리를 먼저 하고 수리 후 검증으로 갈음할 것인가 |
| 감사 권고 | **Tier 0 수리를 먼저** 하는 편이 낫다 — B4/B5(`run()` rc 폐기)를 고치면 B6·B7을 포함한 다수가 함께 닫히므로, 재감사는 그 뒤에 하는 것이 정보량이 크다 |
| 미결 시 | 호스트 안전체계 설치/제거가 **실패해도 PASS를 보고할 수 있는 상태**가 유지된다. 이 세 파일은 호스트 하드다운 방어 계층이라 미결 비용이 가장 크다 |

### D6. 이 보고서를 공유용 HTML 아티팩트로도 발행할 것인가

| | 내용 |
|---|---|
| 사실 | 현재 정본은 이 `.md` 파일이며 `docs/report/`는 **유일한 추적 예외**라 클론에 그대로 실려 배포된다(`.gitignore` `!docs/report/*`). 같은 폴더에 `.html` 선례가 2건 있다(`audit_26082110_*.html` · `perf_26071619_*.html`) |
| 갈림 | HTML 아티팩트를 추가하면 링크 공유가 쉬워지지만 **정본이 둘이 되어 갈라진다**(이 저장소의 규율: 중복은 갈라져 침묵 누락을 만든다) |
| 감사 권고 | 배포 대상이 저장소 클론 이용자라면 **`.md` 단일 정본 유지**. 저장소 밖 사람에게 링크로 보여줄 필요가 생기면 그때 **파생물임을 명시**하고 발행 |
| 미결 시 | 영향 없음 — `.md` 정본은 이미 배포 경로에 있다 |
