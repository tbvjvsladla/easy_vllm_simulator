## 2. 핵심 축 — PLE mmap vs resident가 서빙 생사를 가른다

컨텍스트 길이(262k/512k/1m) · 체크포인트 변종(NVFP4/FP8) · KV dtype(auto/fp8) 어느 조합에서도
PLE mmap 축을 벗어난 예외 없이 재현됐다(§4의 레거시 1건 제외).

- **mmp(PLE mmap) 계열 12/12 성공** — 262k 4종 + 512k 4종 + 1m 4종 전부 PASS. t/s 범위 33.27~38.18.
- **res(PLE resident) 계열은 체크포인트 크기에 따라 실패 기전이 갈린다**:
  - **NVFP4(123.57GiB, 작은 체크포인트)** — 예산 선판정은 항상 통과한다(floor=16,064MiB, 양수·context
    무관 고정값). 그러나 실제 로드 중(`determine_available_memory` RPC 단계) 실측 상주메모리가 예측을
    초과해 워치독에 사살된다. 재현: 262k 1건(`nv4-f8-262k-res`) + 512k 2건 + 1m 2건 = **5/5**.
  - **FP8(172.78GiB, 큰 체크포인트)** — 예산 선판정 단계에서 즉시 음수 floor(−9,134MiB)로 차단된다
    (로드 0초, GPU 비용 0). 재현: 262k 2건 + 512k 2건 + 1m 2건 = **6/6**.
  - KV 절대클램프(20,480MiB 고정)는 **context 길이 무관**임이 3개 그룹에서 반복 확인됐다 — 동일 변종의
    floor 값이 262k·512k·1m 전부 정확히 일치한다.

## 4. 정직성 노트 — nv4-bf-262k-res 레거시 "성공"은 재현 대상이 아니다

24전략 표에서 **유일하게 res 축이 성공한 셀**은 `nv4-bf-262k-res`(레거시, 32.53 t/s)다. 이것이
"resident 모드도 262k에서는 괜찮다"는 결론으로 읽혀서는 안 된다 — 이유는 다음과 같다:

1. **이 측정은 R0~R10 하네스 교정 이전**(`camp-26090918`, 2026-09-10 이전)의 환경에서 나왔다. 이번
   22셀 재수행 캠페인이 존재하는 이유 자체가 그 캠페인의 24셀 중 21셀이 사인 오진이었기 때문이다
   (`docs/testlog/testlog_26091109_하네스교정_R0R10_역채점_음성대조.md`). 워치독 임계값·예산 게이트
   구성이 현재와 동일했다는 보증이 없다.
2. **같은 res 축(NVFP4+resident)을 하네스 교정 후 재시험한 5건(`nv4-f8-262k-res` +
   `nv4-{bf,f8}-512k-res` + `nv4-{bf,f8}-1m-res`)은 전부 워치독 사살로 실패**했다 — 동일 floor
   (16,064MiB) 위에서 5전 5패다. `nv4-bf-262k-res`만 성공한 것은 재현되지 않는 예외로 다뤄야 한다.
3. 원 hint 태그 자신이 **"OBSERVATION-ONLY. 인증서가 없다 — baseline이나 권고로 승격하지 마라"**고
   명시하고 있다(§7 메타: 24셀 중 measured 3 / void 21).

**결론**: 24전략 중 **실질적으로 신뢰 가능한 권고 축은 mmp 12/12**이며, res 축은 (레거시 1건의
불확실한 예외를 제외하면) **12/12 실패**로 취급하는 것이 안전하다.

## 5. R8(YaRN 컨텍스트 확장) 검증 — 512k·1m 전 조합 완결

262k는 모델 네이티브 상한이라 YaRN이 불필요하다. 512k(factor=2)·1m(factor=4) 양쪽에서
`mrope_interleaved=true · partial_rotary_factor=0.25 · rope_theta=10000000 · rope_type=yarn ·
original_max_position_embeddings=262144` 오버라이드 위에 YaRN factor만 전환하는 방식이 NVFP4/FP8
변종, auto/fp8 KV dtype 전 조합(8셀)에서 정상 동작을 재현했다 — 완결 엔드포인트 추론 정합까지 확인.

## 6. hint 태그 카탈로그 — mmp 12전략 전부 발행 완료

24전략 중 mmp 계열 12개 전략 전부가 `hint/0.29.0/qwen3.8-flash-next-{nvfp4,fp8}/gb10x2-cluster-native/`
아래 발행돼 있다(`HINTS.md` 참조). res 계열 12개는 실패 전략이므로 hint 미발행이 정상이다(성공
레시피만 hint로 배포한다).

| 262k-auto | `len262144-kvauto`⚠구태그 | `len262144-kvauto-plemmap` |
| 262k-fp8e4m3 | `len262144-kvfp8e4m3-plemmap` | `len262144-kvfp8e4m3-plemmap` |

(`len262144-kvauto` / `len262144-kvauto_260910t0204z`, 이름 충돌로 타임스탬프가 붙음). 재발행하면
이름 정합은 맞지만 §4의 이유로 res 쪽은 재발행 대상이 아니고, mmp 쪽(`nv4-bf-262k-mmp`)은 새 명명
규약으로 재검증·재발행할 가치가 있다 — 이번 리포트 범위 밖 후속 과제로 남긴다.

## 7. 알려진 배선 결함(누적, 최종)

- 서브측 워치독은 두 개의 독립 인스턴스(ad-hoc non-journald / systemd L1 유닛 `easy-vllm-memwatch`)로
  나뉘며, 262k~1m 전 구간에서 둘 다 최소 1회씩 실제 사살을 집행했다. journald 경유 유닛은
  `blackbox_events.py`를 서브에서 직접 실행해 자동 수확 가능하다.
- 메인 노드 `--keep-up` 워치독·예산갱신 루프의 과거 `&`(비-setsid) 결함은 이번 22셀 전 구간에서
  재발하지 않았다(Monitor 기반 실행으로 전환한 이후 안정).
- 브랜치 전환(single-node → multi-node, 512k 그룹 도중 사용자 지시로 수행)은 데이터 손실 없이
