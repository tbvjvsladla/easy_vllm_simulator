## 결론

선행 감사는 정적 독해 + 격리 저장소 E2E 였다. 그 뒤 **처음으로 라이브 발행이 한 번 완주**했고
(`hint/0.19.1/gpt-oss-120b/gb10-single`), 그 한 번이 **픽스처가 구조적으로 볼 수 없던 것 두 가지**를
드러냈다.

1. **발행이 규약을 어겼다.** 태그가 `plan_26090107` 이 폐기하기로 한 옛 규약대로
   **코드 브랜치 커밋**을 가리킨다. 그 archive 는 302 파일 프로젝트 스냅샷이고 **192개(63.6%)가
   `.claude/`** 다. 계획 §12 합격기준 **A1**(archive 에 `.claude/` 엔트리 0)의 정면 위반이다.
   — 이 항목은 **사용자가 먼저 지적했다.**

2. **PII 방어가 배포면의 20%를 보지 못했다.** 트리 스캐너의 확장자 allowlist 에 `.sh` 가 없어,
   추적 배포 빌딩블럭 190개 중 **38개가 스캔 사각지대**였다. 그 사각지대에서 **운영자 절대경로
   실누출 2계열**이 이미 원격에 배포된 채 살아 있었다. 스캐너는 그 파일들을 두고 `PASS 0 hits` 를
   출력했다.

두 번째가 더 무겁다. 첫 번째는 *잘못 발행한 것*이고 되돌릴 절차가 이미 있지만, 두 번째는
**게이트가 통과를 선언한 자리에 결함이 있었다**. 선행 감사의 §방어층 실효 분석이 *"남는 실효 방어가
사실상 ③ 하나"* 라고 적었는데, ④(PII)는 **하나로 세지도 못할 상태**였다.

동시에 **fail-closed 는 여러 번 제대로 작동했다** — 선행 request 지시서가 자기 Step 1 로 이 오발행을
잡았고(§2.2), `finalize` 는 `pii_terms` 부재로 발행을 막았으며, 색인 갱신은 권위 미선언으로 막혔다.
설계가 나쁜 것이 아니라 **배선이 닿지 않은 곳이 남아 있었다** — 선행 감사의 체계적 진단 그대로다.

## 1. 라이브 발행이 드러낸 것 (픽스처가 못 보던 평면)

| # | 관측 | 선행 감사에서의 지위 |
|---|---|---|
| L1 | 태그가 코드 브랜치 커밋을 지시 → archive 63.6% 가 `.claude/` | 감사 항목 밖(계획 §2.1 이 다룸). **A1 위반**으로 재분류 |
| L2 | `_brief_of` 가 템플릿 경고 HTML 주석을 brief 로 캐냄 | ⑤ 의 **기전이 여전히 살아 있음**을 감사자가 직접 겪음 |
| L3 | `finalize` 가 `.claude/pii_terms.txt` 부재로 차단 → 감사자가 그 파일을 **생성** | ⑫ 가 예측한 *"배포 클론의 기본 상태가 부재 → 다음 유인"* 의 현실화 |
| L4 | `index --tag` 로 무검증 `status: active` 기입 | ④ 를 감사자가 **정규 절차로서** 통과 |
| L5 | `push` 가 PII 스캔 0회로 원격 배포 | ⑫ 후반부 그대로 |

> **L2 가 중요한 이유**: ⑤ 는 *"이미 발생한 손상"* 으로 분류돼 있었다. 그런데 새 발행이 **같은 방식으로
> 다시 오염됐다** — 손상이 아니라 **재발 중인 기전**이다. 감사자가 손으로 잡았고 게이트는 잡지 않았다.

## 2. 신규 발견

### N-1 (심각도 1) — PII 스캐너가 배포 빌딩블럭의 20%를 보지 못한다 · **실누출 2계열** (실측)

`scan_forbidden_strings.py` 는 확장자 allowlist 로 대상을 골랐다:

```
TEXT_EXT = {".md", ".py", ".yaml", ".yml", ".json", ".txt", "", ".example"}
```

`.sh` 가 없다. 추적 `.claude/` 파일의 확장자 분포(실측)는 `py 73 · md 41 · **sh 28** · json 27 ·
yaml 11 · template 4 · patch 2 · golden 2 · service 1 · 기타 1` 이므로 **38/190 = 20%가 사각지대**였다.

그 사각지대에 실제 누출이 있었다:

| 계열 | 위치 | 성질 |
|---|---|---|
| 운영자 홈 경로 ×3 | `.claude/skills/**/*.sh` 주석 3곳 | 사고 서술 주석. 무해하지만 **환경 지문** |
| 운영자 NAS 절대경로 ×1 | `.claude/policies/provenance/plan_26062818_*.md` | `<nas_model_path>` 실값이 배포 추적물에 리터럴로 |

`docs.md` §PII 적용범위는 `.claude/**` 를 **배포 산출물 = 4종 전부(`abs-op-path` 포함)** 로 규정한다.
네 건 모두 규약 위반이고, 넷 다 **이미 원격에 push 되어 있었다**.

**음성대조 (교정 전/후 · 같은 대상)**

```
교정 전 :  PASS forbidden string scan: 0 hits          rc=0   ← 거짓 통과
교정 후 :  HIT …/verify_node_blackbox.sh: term:…       rc=1
           HIT …/install_node_blackbox.sh: term:…
           HIT …/install_netconsole.sh: term:…
```

**처방(적용됨)**: 확장자 allowlist 를 **제거**했다. `read_text` 의 `UnicodeDecodeError` 가 이미
바이너리를 거르므로 확장자 판정은 중복이면서 유해했다 — 내용으로 판정한다. 크기 상한(4 MiB)과
판독 실패는 **소리내어**(`SKIP(...)`) 보고한다. 조용히 건너뛴 파일은 "깨끗한 것"과 구분되지 않는다.

### N-2 (심각도 2) — 밴드 승격이 PII 재판정을 타지 않는다 (실측 · N-1 의 NAS 누출 기전)

NAS 경로 누출의 경로가 정확히 이것이다:

```
docs/plan/plan_26062818_*.md            비배포 산문 → 3종 스캔(abs-op-path **면제**)
        │  sync: apply self-contained control plane (bc8c54c)
        ▼
.claude/policies/provenance/…같은 파일    배포 산출물 → 4종 스캔(abs-op-path **강제**)
```

**내용은 그대로 옮겨졌고 강도만 바뀌었다.** `docs.md` 의 적용범위 표는 "무엇을 어느 강도로 보는가"를
정확히 규정하지만, **밴드를 넘는 이동 자체를 잡는 게이트가 없다.** 면제받던 문장이 강제 구역으로
걸어 들어가도 아무도 다시 묻지 않는다.

**처방(미적용 · 사람 판단 필요)**: 배포 밴드로 승격되는 파일에 대해 승격 시점 4종 스캔을 강제한다.
자연스러운 자리는 `sync_branches.sh` 와 `sync_to_sub.sh` 의 배달 표면이다.

### N-3 (심각도 2) — PII 스캔의 사정거리가 **태그가 배포하는 트리**에 닿지 않는다 (대조)

`hint_tag.py` 의 `ls-tree` 호출 **0건**. 스캔 대상은 이렇게 갈린다:

| 명령 | 스캔 대상 |
|---|---|
| `finalize`/`seal` | 태그 **본문** + evidence footer + tagger 신원 |
| `verify` | 태그 오브젝트 + 워킹트리 `output/*/build_patches/*.sh` glob |
| **태그가 실제로 배포하는 트리(archive)** | **어느 명령도 보지 않는다** |

현행에서는 트리가 추적물뿐이라 실질 위험이 낮다 — **다만 그 전제가 N-1 로 이미 깨져 있었다.**
그리고 계획 D1.2 가 트리를 allowlist 로 짓게 되면 **미추적 devlog·`.env.<model>` 이 트리에 올라온다.**
그 순간 이 공백이 계획 R1 그대로 터진다.

**이 항목의 요지는 "지금 새고 있다"가 아니라 "방어가 이사 가지 않았다"이다.** 게이트는 *본문*을
지키도록 설계됐는데 새 아키텍처는 *트리*를 배포한다. Phase 4 의 페이로드 PII 게이트가 이것을
소유해야 한다.

### N-4 (심각도 2) — 두 스캐너의 패턴 집합이 갈렸다 · 배포 클론에서 4종 중 1종만 산다 (실측)

| 스캐너 | generic 패턴 | 비고 |
|---|---|---|
| `hint_tag.GENERIC_PII` | **4종** — private-ipv4 · email · abs-op-path · spark-host | `docs.md` 가 지목한 **정본**. `_SECTION_ANCHOR` 판별자까지 갖췄다 |
| `scan_forbidden_strings.GENERIC_PATTERNS` | **1종** — RFC1918 사설대역 3블록 중 `/16` 하나의 접두만 | 트리를 보는 유일한 스캐너 |

리터럴 목록(`pii_terms.txt`)은 **비추적**이므로 배포 클론에는 없다. 따라서 배포 클론에서 트리 스캐너가
실제로 잡는 것은 그 사설대역 접두 하나뿐이고, **운영자 절대경로·이메일·호스트명·나머지 사설대역은
탐지 자체가 불가능**하다.

이것이 N-1 을 더 무겁게 만든다 — 확장자를 고쳐도, **배포 클론에서는 여전히 못 잡는다.**
이 저장소에서 3건이 잡힌 것은 로컬 `pii_terms.txt` 가 마침 그 리터럴을 담고 있어서였다.

**파급 실측** — 정본 4종을 `.claude/` 에 적용하면 42건이 매치한다. 분류:

| 분류 | 건수 | 예 |
|---|---|---|
| **실누출** | **0** (교정 후) | — |
| 탐지기 자기 픽스처 | 5 | 사설 IP 양성 케이스 1 · manifest 픽스처 IP 2쌍 |
| RFC 예약 도메인 | 8 | `example` 계열 · `.invalid` 계열 |
| 일반 플레이스홀더 | 27 | 범용 모델 마운트 경로 (운영자 지문 아님) |
| 오탐 | 2 | git SSH URL · 프로젝트 합성 신원 |

**처방(미적용 · 정책 판단 필요)**: 트리 스캐너가 정본 4종을 **hint_tag 에서 import** 하게 하면 단일
소유가 성립한다. 다만 그 순간 37건의 픽스처·플레이스홀더에 면제 표기가 필요하다. *어디까지가
플레이스홀더인가*는 정책 판단이라 사람에게 넘긴다 — §6 결정 대기.

### N-5 (심각도 3) — 무결성 게이트가 8시간 빨간불이었고 아무도 몰랐다 (실측)

Phase 1 은 `hint_tag.py` 를 456행 줄였으나 **digest 를 재기록하지 않았다.** 그래서
`verify_distribution` 의 `tracked_index_all_entry_bytes` 가 08시부터 FAIL 이었다.
**그 상태에서 태그 1건이 발행·push 됐다.** 게이트가 배포를 막지 않은 이유는 단순하다 —
발행 경로가 `verify_distribution` 을 부르지 않는다(선행 감사 §권고 말미의 *"등재가 곧 배선이다"*).

부수 관측: `bootstrap_families.py` 와 `runtime_selftest.py` 는 `tracked_index` 에 **등재 자체가 없다**.
terraforming 감사가 기록한 *"tracked_index 가 node_blackbox 18파일 중 4개만 덮는다"* 와 같은 계열이다.

### N-5b (심각도 2) — 스캐너가 `docs/report/` 위를 한 번도 돈 적이 없다 · **배포 리포트 누출 1건** (실측)

이 재감사가 **자기 리포트를 스캔하다가** 우연히 드러났다. `docs.md` 는 `docs/report/*` 를
*"유일한 tracked docs 산출물 예외 · 배포 산출물 = 4종 전부"* 로 규정하는데, 실제로는
`harness_26082218_*_TTSC_증거_그래프_원칙_구현.md:4` 에 **운영자 절대경로가 실려 원격에 배포돼 있었다.**

N-1(확장자 사각지대)과 **기전이 다르다** — `.md` 는 언제나 스캔 대상이었다. 문제는
**아무도 그 디렉터리 위에서 스캐너를 돌리지 않았다**는 것이다. 만들어진 것과 도는 것의 차이가
여기서도 같은 모양으로 나온다.

부수 관측: `docs/report/*` 는 배포되지만 `tracked_index`·`evidence_manifest` 어디에도 **등재가 0건**이다.
무결성 게이트가 배포 산출물의 한 축을 통째로 비워 두고 있다.

**처방(교정 완료)**: 해당 경로를 `<repo>` 플레이스홀더로 치환. `docs/report/` 전량 재스캔 결과
스캐너 `PASS`(0 hits) · 정본 4종 직접 대조 **0건**.
**미적용**: 릴리즈 게이트에 `docs/report/` 스캔을 배선하는 것(§6 D3 과 같은 자리).

### N-6 (심각도 3) — `.gitignore` 가 `.claude/policies/` 하위 3개 디렉터리를 재포함하지 않는다 (실측)

`.gitignore:42` `.claude/policies/*` 뒤의 재포함 목록(43–50)에 `predicates/`·`provenance/`·`runtime/`
가 **없다**. 기존 파일은 이미 추적 중이라 정상으로 보이지만, **그 디렉터리의 신규 파일은 `git add`
가 조용히 no-op** 이 된다. 이번 교정에서 `git add` 가 실제로 경고를 냈다.

## 7. 이 재감사 자체의 한계

- **`push` 는 여전히 미시험이다.** 네트워크 경로라 격리 저장소에서 재현하지 않았다. ⑫(push PII 0회)는
  코드 대조로만 확인했다.
- **①의 우회(`create` 를 건너뛴 `seal`)는 이번에도 시험하지 않았다.** 선행 감사가 지목한 회귀망 공백
  (프로브가 항상 `create→seal`)이 그대로다. 계획 §12 A8 이 이것을 소유한다.
- **N-4 의 분류 37건은 감사자의 판단이다.** 범용 모델 마운트 경로를 "플레이스홀더"로 본 것은
  문맥 독해이며, 기계가 확증한 것이 아니다. D2 를 사람에게 넘기는 이유다.
- 선행 감사의 자기 결함 기록(*"부정 주장은 도구 하나의 출력으로 확정하지 않는다"*)을 이번에 적용했다 —
  N-1 의 `PASS 0 hits` 를 그대로 믿지 않고 `grep` 으로 반증한 것이 발견의 계기였다.
