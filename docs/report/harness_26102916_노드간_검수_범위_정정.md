# 노드 간 검수 범위 정정

작성일: 2026-10-29 KST. 상태: 사용자 정정을 반영한 범위 복구. 앞선 [검증 트리거와 재검증 제어 설계](harness_26102916_검증_트리거와_재검증_제어_설계.md)의 과도한 제안을 철회한다. 새로운 헌장·코드 개정은 수행하지 않았다.

## 정정 이유

인터뷰의 현재 쟁점은 노드 간 검증의 과도함을 줄이고 드문 예외의 처리 범위를 정하는 것이다. create/maintain 자료는 영감을 얻을 참고자료였다. 이를 새 검증 경로 생성·일상 변경·전체 유지보수라는 운영체계로 확대해 노드 간 정책에 붙인 것은 작성자의 범위 설정 오류다.

해당 세 가지 모드, 새 기능 맵, 일반 검증 원장과 범용 차단 경로, hint 보고 형식 개정 및 전체 검증 체계의 재설계는 이번 노드 간 정책의 필수 범위에서 제외한다. 앞선 확대안은 승인된 요구사항으로 취급하지 않는다.

## 이번에 유지할 정책

**정상 시에는 기존 결과를 인수한다. 실제 문제가 드러난 경우에만 이미 정한 토폴로지별 범위에서 처리한다.**

단일 노드의 기존 workflow는 반복 E2E로 신뢰성을 확보했고, 검증된 공통 변경을 메인에서 서브 런타임으로 전파해 왔다는 사용자 제공 운영 전제를 유지한다. 노드 경계를 넘었다는 사실만으로 신뢰를 초기화하거나 별도 재검증을 요구하지 않는다.

| 상황 | 메인의 처리 |
|---|---|
| 정상적인 결과 반환 | 기존 문서를 인수하고 메인 소유의 오케스트레이션·카탈로그 업무를 수행한다. 추가 검증을 상시 단계로 두지 않는다. |
| 싱글의 구체적인 문제 발견 | 해당 항목을 서브에 설명·정정 요청하고 수정된 반환 결과를 인수한다. |
| 멀티의 분산 연결 문제가 설명·정정 후에도 남음 | 해당 쟁점에 한해 서브가 제출한 추가 근거를 확인한다. |

문제 발견의 출발점은 기존 반환 결과에서 드러난 실제 누락·모순·연결 문제다. 이를 찾아내기 위한 새 전수 감사나 원시 재수집을 상시 추가하지 않는다. 동일한 결과·쟁점에서 새 변경이나 문제가 없으면 같은 확인을 되풀이하지 않는다.

실제로 발생한 희귀 예외에는 전체 재검증을 문서상 허용할 수 있다는 기존 합의도 유지한다. 이 허용은 상시 발동 절차나 싱글 메인의 서브 전체 감사 권한으로 확장하지 않는다. 기존 업무 소유·승인 경계 안에서 다루며, 이번 정정으로 별도의 상세 트리거 분류나 새 승인 체계를 만들지 않는다.

## 참고자료에서 얻을 최소한의 영감

| 자료 | 이번 쟁점에 참고할 내용 |
|---|---|
| create-verification-skill | 실제 사용자 경로와 관찰 가능한 결과를 근거로 삼고 기존 하네스를 우선한다. |
| Maintain a verification skill | 이미 확인한 주장을 처음부터 다시 증명하지 않고 겹치는 확인을 합친다. |
| unlazy | 기존 상태와 근거를 사용해 완료된 일을 반복 실행하지 않는 구조를 참고한다. 부모의 무조건 재실행은 가져오지 않는다. |

코드 보강은 기존 인수·feedback 경로에서 불필요한 재검증 지시의 반복을 최소한으로 억제할 필요가 있는지에 한정해 후속 검토할 수 있다. 이를 이유로 새 검증 플랫폼이나 별도 유지보수 workflow를 선행 설계하지 않는다.

## 헌장 배치와 인터뷰 상태

공통층의 아스트라 작업 원칙 채택, 싱글·멀티의 서로 다른 검수 범위, 각 브랜치 특화 헌장에 그 범위를 등록한다는 기존 합의는 유지한다. 구체적인 토폴로지별 검수 정책은 각 브랜치의 `.claude/rules/strategy.topology.md`에 둔다.

앞선 확대 설계의 확인 요청은 회수한다. 이 문서는 사용자의 범위 정정을 반영하며, 확대안의 코드 구현이나 새 검증 절차를 승인받은 것으로 기록하지 않는다. 후속 논의는 드문 노드 간 예외를 기존 절차 안에서 간단히 표현하는 범위로 돌아간다.

## 근거

- 사용자 정정: 인터뷰의 대상은 과도한 노드 간 검증이며 두 자료는 영감을 얻는 참고자료다. 대부분 노드 간 검증이 발생하지 않는다는 운영 전제에서 드문 예외를 다룬다.
- [생성 참고자료](<../../seed/헌장 개정용 배경자료/create-verification-skill.md>) §1 기존 하네스 우선·실제 사용자 경로.
- [유지보수 참고자료](<../../seed/헌장 개정용 배경자료/Maintain a verification skill.md>) Pass 3의 중복 재증명 억제·레시피 병합. 해당 유지보수 패스를 이번에 발동한 것은 아니다.
- [unlazy 실행 선택](../../seed/unlazy/scripts/gate-check.mjs)의 일반 모드에서 이미 `met`인 게이트를 건너뛰는 분기. 노드 간 정책 자체가 패키지에 구현되어 있다는 뜻은 아니다.
