## 환경 특이사항 (재현 시 필독)

이 캠페인은 **Docker를 쓰지 않는 환경**(비특권 컨테이너 — Docker-in-Docker 구조적 불가)에서 수행됐다.
이 프로젝트의 표준 산출물(NGC 베이스 컨테이너·`docker compose` 서빙)은 Docker 를 전제하므로, 이번
캠페인 한정으로 다음과 같이 대체했다:
- 컨테이너 빌드 대신 vLLM 0.28.0 + torch 2.13.0(+cu129)을 프로젝트 전용 `.venv` 에 벤더 wheel로 직접 설치.
- 서빙은 `docker compose up` 대신 `vllm serve` 를 이 호스트의 네이티브 프로세스로 직접 기동
  (GPU 격리는 `CUDA_VISIBLE_DEVICES` 로 수행).
- 측정 도구(GuideLLM)도 별도 컨테이너 대신 pip 패키지로 직접 설치·실행.
- Docker 환경에서 재현할 때는 이 대체가 불필요하며, 표준 3종 세트(`output/single/configs/*.{yaml,sh}`,
  `envs/.env.*`)를 그대로 `docker compose` 로 띄우면 된다(단, 아래 KV 절대클램프·batch·양자화 값은
  이 GPU 예산 기준 실측이므로 동일 GPU/동일 TP 에서만 그대로 유효하다 — 다른 GPU 면 재측정 권장).
- **셀 D(YaRN 524288) 재현에는 추가 선행조건이 있다**: 이 프로젝트의 레시피 생성기
  (`gen_recipe_set.py`)가 YaRN 확장에 필요한 `--hf-overrides` CLI 플래그를 처음엔 지원하지
  않았다(SERVE_KNOB_KEYS 닫힌열거 밖). 이번 캠페인 도중 `hf_overrides` SERVE_KNOB 을 생성기에
  추가해 해소했다 — 이 프로젝트를 그대로 쓰는 재현자는 별도 코드 작업이 필요 없다(이미 반영됨).

## 핵심 인사이트

1. **KV 양자화가 이 하드웨어에서 동시접속 처리량의 지배 변수다.** 가중치양자화가 같은 A/B 비교에서
   단일 스트림 속도는 거의 동일(43.91 vs 44.22)하지만, KV를 fp8로 줄인 B만 batch=6까지 늘릴 수 있어
   집계 처리량이 **9배** 차이난다. "최대 context + 남은 KV로 동시접속 유지" 전략에서 KV 양자화가
   최우선 레버다.
2. **가중치 양자화(fp8 vs bf16)는 단일 스트림 속도에 ~1.6배 영향**(43.9 vs 26.8) — 메모리 대역폭
   결정 레짐에서 예상된 방향이다. 정확도가 더 중요해 bf16 이 필요한 경우, 처리량 저하를 감수하는
   대안으로 유효(셀 C도 PASS).
3. **YaRN 으로 컨텍스트를 4배(262144→524288) 늘려도 단일 스트림 decode 속도는 거의 변하지 않는다**
   (셀 D 44.27 t/s ≈ 셀 B 44.22 t/s, 같은 fp8w+fp8kv 조합). 이 실측(input=1024/output=256) 조건에서는
   실제 사용 컨텍스트가 선언된 상한보다 훨씬 짧아, decode 비용이 상한 자체가 아니라 KV 에 실제로
   쌓인 토큰 수에 좌우되기 때문이다 — 매우 긴 프롬프트나 누적 멀티턴 컨텍스트에서는 이 결론이
   그대로 적용되지 않을 수 있다(이 벤치는 그 영역을 측정하지 않았다).
4. **YaRN 은 처리량이 아니라 "컨텍스트가 필요한 용처"에 값을 낸다.** 셀 D 의 동시접속 한계(batch=3)
   는 셀 B(batch=6)의 절반이라 집계 처리량은 낮지만(628.7 vs 1181.6), 262144 로는 안 들어가는
   프롬프트/문서를 다뤄야 하는 용처에서는 유일한 선택지다.
5. **네이티브 262144 컨텍스트가 이 GPU 1장 예산의 "손쉬운" 상한이지만, 물리적 절대 상한은 아니다.**
   1차 판단(구 3셀 리포트)은 YaRN 을 이 GPU 1장으론 물리적으로 불가하다고 잠정 결론했으나, 이는
   실측이 아니라 안전마진 추정이었다 — 실제로는 셀 D(524288)가 batch=3 로 안정적으로 PASS 했다.
   **더 큰 확장(1M)은 여전히 미검증**(모든 조합에서 물리 예산 초과 추정, 이 GPU 1장으론 불가할
   개연성이 높음 — 필요시 별도 트라이얼 필요).

  트라이얼로 확인). 참고: 다른 하드웨어(DGX Spark GB10) 기준 수동 검증 선례는
