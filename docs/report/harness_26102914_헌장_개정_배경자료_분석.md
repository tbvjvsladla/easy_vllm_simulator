# 헌장 개정 배경자료의 원칙과 적용 조건 분석

분석일: 2026-10-29 KST. 대상은 `seed/헌장 개정용 배경자료/`의 문서 3편이다. 현재 체크아웃의 `CLAUDE.md`, workflow·docs·토폴로지 규칙과 대조했다. 이 보고서는 제공된 자료의 논지와 적용 조건을 분석하며, 헌장이나 실행 정책을 개정하지 않는다.

핵심 결론은 **보호해야 할 결과·권한·완료 기준을 고정한 상태에서, 작업 방법을 과도하게 지정하는 지침과 정보 전달 비용을 재평가하자**는 것이다. 세 문서는 지침 삭제량, 에이전트 수, 짧은 답변을 개선 지표로 삼지 않는다. 이 저장소에는 기존 계약의 제거보다 적용 조건의 명확화, 중복 지시의 통합, 변경 영향에 맞는 검증 범위 선택으로 연결하는 편이 적절하다.

## 1. 패키지 구성과 근거의 성격

| 자료 | 담당하는 질문 | 근거의 성격과 한계 |
|---|---|---|
| [B1 지침을 줄이고 검증을 남기는 Agent 운영법][B1] | 어떤 지침을 어떤 조건에서 줄일 수 있는가 | 영상의 문제의식을 재구성한 방법론 제안이다. 보리스 체르니의 직접 발언록이나 공식 운영 지침이 아니다. |
| [B2 아스트라 계열 LLM 작업 원칙][B2] | 일상 작업에서 불필요한 읽기·질문·수정·검증을 어떻게 줄이는가 | 8개 절의 정리본과 뒤쪽 6개 절의 원문이 함께 들어 있다. 특정 모델의 성능 실험이나 런타임 설정 명세가 아니다. |
| [B3 Anthropic 서브에이전트 통합론 해설][B3] | 무엇을 메인 루프로 합치고 무엇을 분리하는가 | 공식 글·영상·외부 연구의 출처를 구분한 2차 분석이다. 인용 원자료의 독립 재검증이나 통합 실험 결과로 취급하지 않는다. |

B3가 가리키는 자막·화면 표본·원문 수집물은 이 패키지의 세 문서에 포함되지 않는다. 따라서 B3의 분석 방법과 출처 대응을 읽을 수는 있어도, 그것만으로 원자료 수집 전 과정을 재현할 수는 없다. 보고서의 모델·연구 관련 수치는 해당 문서가 기술한 조건부 주장으로만 읽어야 한다.

세 자료의 역할은 겹치면서도 다르다. B1은 지침을 바꾸는 비교 방법, B2는 실제 작업자의 행동 선택, B3는 에이전트·스킬·도구 사이의 책임 배치를 다룬다. 이를 하나의 긴 상시 프롬프트로 합치면 세 문서가 줄이려는 중복을 다시 만들 수 있다.

## 2. B1 분석 지침을 역할별로 나누는 개정 방법

B1 §2는 지침을 보호 규칙, 업무 계약, 행동 보정 지시, 작업별 지식으로 나눈다. 이 분류의 장점은 문장의 형태보다 그 지침이 지키는 대상을 먼저 묻는다는 데 있다.

| 분류 | 저장소에서 대응되는 예 | 개정할 때의 판단 |
|---|---|---|
| 보호 규칙 | 승인 없는 모델 획득·외부 전송·위험한 호스트 변경 제한 | 지능 향상을 근거로 삭제하지 않는다. 변경하려면 해당 정책의 권한과 검토를 별도로 다룬다. |
| 업무 계약 | manifest의 권위, 산출물 통로, 기능 스모크·성능 완료의 구분 | 구현 방법을 바꾸어도 완료 기준은 유지한다. |
| 행동 보정 지시 | 모든 변경에 동일한 순서·같은 재독·같은 전체 검사를 반복시키는 지시 | 실제 실패 이력과 현재 효과를 확인한 뒤 제거·조건화 후보로 삼는다. |
| 작업별 지식 | 특정 빌드 트랙·모델·토폴로지의 상세 절차 | 해당 스킬·참조에서 필요한 시점에 제공한다. 발견 경로까지 없애지 않는다. |

중요한 제한은 분류 자체가 삭제 허가가 아니라는 것이다. 예를 들어 ‘먼저 A를 하고 B를 하라’는 문장도 승인 선행이나 ABI 의존성을 보장한다면 단순 행동 보정이 아니다. 혼합된 문장은 먼저 보호 조건과 선택 가능한 방법으로 나누어야 한다. [B1 §2·§4][B1]

B1 §3의 비교 절차는 기준선·수용 기준·복원 조건을 먼저 고정하고 해석 가능한 작은 변경을 시험한다. 정상 입력만 아니라 과거 실패·경계·중단 상황을 포함하며, 결과가 부족하면 ‘보류’를 허용한다. 이 때문에 ‘문서가 짧아졌다’와 ‘실제 운영이 나아졌다’를 구분할 수 있다.

다만 제공된 YAML 실험 기록서는 측정 설계의 틀이다. 실행 도구, 과제 집합, 통계적 충분성, 합격 임계값을 자동으로 제공하지 않는다. 저장소에 적용한다면 먼저 하나의 실제 개정 후보와 그 후보가 일으켰던 비용 또는 실패를 정해야 한다.

## 3. B2 분석 자율 실행과 필요한 검증의 균형

B2의 정리본은 결과·범위를 파악하고, 필요한 자료를 읽고, 승인된 작업을 완수한 뒤 수용 기준만큼 검증하고 종료하는 흐름이다. 불필요한 질문을 줄이면서도 외부 영향·권한 확대·지속 설정 변경은 승인 경계로 구분한다. [B2 §1–§5][B2]

가장 실용적인 조항은 **통과한 검사에서 입력·결과가 바뀌지 않고 미해결 위험도 없으면 반복하거나 범위를 넓히지 않는다**는 원칙이다. 이는 검사를 생략하라는 뜻이 아니다. 시작할 때 정한 필수 검사와 변경 영향에 따른 검사를 끝내고, 새로운 실패나 변경이 있을 때만 추가 검사를 선택하는 방식이다.

원문은 불필요한 전체 재독, 로그 복사, 저밀도 요약, 무관한 자료 로딩, 해결된 문제의 재탐색을 줄이는 여섯 가지 지침을 제시한다. 정리본은 이를 승인·진실성·최소 변경·병렬화·상태 보존까지 확장한다. 이 확장 부분을 모두 원문 저자의 직접 주장으로 귀속해서는 안 된다.

B2의 재독 제한은 적용 지침을 끝까지 읽으라는 조건과 양립한다. 의무 지침을 생략하거나 잘린 출력을 확인하지 않는 것이 아니라, 이미 확보한 내용을 재사용하고 변경·누락·최신성 문제에 필요한 부분만 다시 확인하라는 뜻이다. 동일하게 짧은 응답과 적은 도구 호출을 실제 토큰·비용 절감의 증거로 삼지 않는다.

또한 문서 제목의 ‘아스트라’는 이 파일의 적용 대상 표현이다. 파일을 읽거나 프롬프트를 붙였다는 사실이 추론 강도·모델·런타임 설정을 바꾸지는 않는다. 이 구분은 이 저장소의 provider 어댑터와 실제 실행 증거 보존 원칙에 잘 맞는다.

## 4. B3 분석 통합 기준은 공유 판단과 독립 결과

B3의 중심 논지는 직무명에 따라 에이전트를 늘리지 말고 정보와 의사결정이 오가는 경계를 보라는 것이다. 동일 사용자 맥락과 산출물의 선택을 계속 공유해야 한다면 한 루프에 두는 편을 검토하고, 좁은 입력과 수용 기준으로 독립 결과를 만들 수 있다면 분리를 검토한다. [B3 §3·§5·§9][B3]

이 구분은 세 가지를 함께 요구한다.

1. 전문 절차는 스킬, 참조 사실은 조회 자료, 실제 승인·금지는 실행 경로가 맡도록 책임을 배치한다.
2. 분리된 문맥이 주는 이득과 전달·재설명·통합 비용을 함께 평가한다.
3. 통합 전후 같은 과제에서 결과 충족·회귀·지연·총비용을 비교한다.

스킬은 필요한 지식을 나중에 읽게 하는 수단이지만 권한 경계는 아니다. 서브에이전트도 별도 문맥이 있다는 사실만으로 OS 격리를 제공하지 않는다. 실제 도구·자격증명·프로세스 제한이 어디에 있는지 따로 확인해야 한다. B3는 통합으로 사라질 수 있는 권한 제한을 명시적으로 검토한다. [B3 §3.3·§6.1·§9.1][B3]

B3가 제시하는 ‘약 2배 빠름’, ‘80% 이상 프롬프트 축소’, ‘90.2% 성과 개선’, ‘54% 스킬 축약’은 서로 다른 대상·분모·환경의 주장이다. 이를 더하거나 이 저장소의 예상 절감률로 바꿀 근거는 없다. 외부 논문에서 선별한 회귀 사례 수 역시 전체 스킬의 실패율을 뜻하지 않는다. 이 보고서는 그 수치를 현행 모델·현재 체크아웃의 실측값으로 사용하지 않는다.

## 5. 세 자료를 함께 읽었을 때의 공통 원칙과 긴장

| 질문 | 공통 방향 | 함께 보존할 조건 |
|---|---|---|
| 지침을 줄일 것인가 | 존재 이유와 현재 효과가 불분명한 행동 보정부터 검토 | 보호 조건·요구사항·완료 기준을 지우지 않는다. |
| 자료를 언제 읽을 것인가 | 관련성과 사용 빈도에 따라 상시 정보와 작업별 참조를 나눈다. | 필요한 지식의 발견 경로와 의무 참조를 유지한다. |
| 언제 분업할 것인가 | 독립된 결과와 명확한 인수 조건이 있을 때 선택한다. | 공유 결정·소유·의존성·통합 책임을 명시한다. |
| 얼마나 검증할 것인가 | 위험과 완료 기준으로 범위를 선택하고 그 범위를 빠짐없이 수행한다. | 미실행·실패를 성공으로 기록하지 않는다. |
| 언제 멈출 것인가 | 필요한 결과와 검증이 끝나면 종료한다. | 실제 차단은 완료와 구분해 인계하고 승인된 후속은 이어간다. |

겉으로 충돌하는 표현은 적용 대상을 나누면 해소된다. ‘전체 검증’은 합의한 수용 범위를 빠짐없이 수행한다는 뜻으로 해석할 수 있고, ‘검증을 줄인다’는 말은 모든 변경에 무관한 검사까지 붙이지 않는다는 뜻으로 적용할 수 있다. 결과를 본 뒤 통과에 유리하도록 수용 기준을 바꾸는 것은 어느 쪽에도 해당하지 않는다.

‘상시 지침을 줄인다’ 역시 모든 정보를 지연 로딩하라는 뜻은 아니다. 자주 쓰고 누락 비용이 큰 계약은 짧게 상시 제공하고, 상세 절차는 스킬 참조에서 해소하는 혼합 방식이 자연스럽다. 이 저장소의 헌법·workflow·스킬·reference 분리도 이미 그 방향을 갖는다.

## 6. 현재 저장소에 대한 적용 판단

다음 표는 자료의 직접 주장과 구분되는 작성자의 적용 판단이다. 개정 실행이나 효과 실측을 뜻하지 않는다.

| 기존 구조 | 자료와의 관계 | 개정 후보 또는 보존 이유 |
|---|---|---|
| 헌법·workflow·스킬·참조의 계층 | 작업별 지식의 조건부 제공과 부합 | 내용을 다시 복제하기보다 적용 조건·정본 포인터가 분명한지 검토한다. |
| manifest와 토폴로지 계약 | 모델 판단으로 대체할 수 없는 업무 사실 | 단순화 대상으로 일괄 삭제하지 않는다. |
| 캠페인 아티팩트와 재개 brief | 장기 상태 보존과 부합 | 기록을 대화 요약과 중복시키지 않되, 승인·결정·잔여 작업은 보존한다. |
| provider 어댑터와 실행 증거 | 실제 하네스와 자기 선언의 구분 | native 실행·도메인 완료의 차이를 유지한다. |
| 정식 completion gate·기능 스모크·벤치 구분 | 관측 가능한 완료 조건과 부합 | 단순 CLI 성공이나 문서 검사로 serving·성능 완료를 대신하지 않는다. |
| 메인과 원격 서브 | 물리 노드·하드웨어·배달·정체성이 결부된 분리 | 같은 코드베이스 안의 직무별 전문가 분할과 동일시해 통합하지 않는다. 노드 내부의 불필요한 역할 중계는 별도 검토할 수 있다. |
| 반복 승인·반복 전체 검사 | 상황에 따라 행동 보정의 중복이 될 수 있음 | 기존 유효 승인을 복구하고, 검사 확대에는 변경·실패·미해결 위험이라는 근거를 요구한다. |

현재 Codex의 main/sub 공통 `:danger-full-access` 설정과도 집행의 종류를 구분해야 한다. manifest·SSH·오케스트레이터는 역할 판단과 승인된 업무 경로를 소유하지만, 그 사실이 로컬 셸의 임의 파일 쓰기를 OS에서 차단한다는 뜻은 아니다. 이 보고서는 앞선 사용자 선택을 되돌리려는 제안이 아니라, **도메인 계약 준수와 실제 접근 차단을 같은 검증 결과로 기록하지 말자**는 해석이다.

## 7. 개정을 검토할 때 사용할 최소 평가 방식

B1의 분류를 활용해 실제로 중복 실행이나 과도한 문맥 로딩을 일으킨 후보 하나를 선택한다. 그 지침이 보호하는 조건과 현재 owner를 먼저 확인한다. 단순히 길다는 이유로 후보를 고르지 않는다.

기준 조건과 변경 조건에는 같은 provider·모델·입력·권한·도구·판정 기준을 사용한다. 정상 과제와 해당 지침의 원래 실패 사례를 포함하며, 성공 여부와 함께 불필요한 읽기·질문·검사·재시도, 전체 완료시간, 관측 가능한 토큰·비용을 기록한다. 독립 실행 순서를 교차하고 반복 수와 중단 조건은 결과를 보기 전에 정한다. 제공 자료만으로 보편적 반복 수나 합격 임계값을 정할 수는 없다.

판정은 제거, 조건부 제공, 복원, 보류로 나눈다. 중요한 경계 위반이나 필수 요구 누락은 평균 비용 감소로 상쇄하지 않는다. 반대로 수용 기준을 충족했고 새로운 위험이 없다면 추가 절차를 계속 붙이지 않는다. 이 방식은 새로운 상시 검사 체계의 설치 없이 기존 plan·testlog·devlog와 캠페인 기록 안에서 설계할 수 있다.

## 8. 최종 판단

이 패키지는 **헌장 개정의 판단 원칙으로 활용할 가치가 높다.** 특히 보호 규칙·업무 계약·행동 보정·작업별 지식을 구분하는 기준과, 합의한 검증을 마치면 멈추는 원칙이 유용하다.

다만 제공 문서만으로 특정 지침의 삭제 효과나 에이전트 통합의 이득이 입증되지는 않는다. 개정의 단위는 문장 수나 에이전트 수가 아니라 실제로 반복 비용을 만드는 하나의 규약이어야 한다. 이 저장소의 권위·승인·토폴로지·완료 기준은 유지하고, 그 위에서 중복과 적용 범위를 검증하는 방향이 타당하다.
