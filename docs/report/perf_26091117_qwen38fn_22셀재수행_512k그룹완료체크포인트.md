## 2. 패턴 확정 — PLE mmap 유무가 512k+ 컨텍스트의 생사 분기축

| 축 | mmp(PLE mmap) | res(PLE resident) |
|---|---|---|
| 262k 그룹 | 3/3 성공 | 1 watchdog_kill · 2 budget_block(3/3 실패) |
| 512k 그룹 | 4/4 성공 | 2 watchdog_kill · 2 budget_block(4/4 실패) |
| **누계** | **7/7 성공** | **0/7 성공** |

- **res 계열의 실패 기전이 둘로 갈린다**: NVFP4(체크포인트 123.57GiB)는 예산 선판정을 통과하고도(floor
  16064MiB, 가드 최소 8192MiB 이상) 실제 로드 중 상주가 예측을 초과해 워치독에 사살된다(예측-실측 괴리).
  FP8(체크포인트 172.78GiB)은 애초에 예산 선판정 단계에서 음수 floor(−9,134MiB)로 즉시 차단된다(로드
  0초, 실 GPU 비용 없음). 둘 다 "resident PLE + 512k 이상 컨텍스트"가 원인이라는 점은 같지만, 관측되는
  실패 시점(로드 전 vs 로드 후반)과 사인(예산 게이트 STOP vs 워치독 TRIP)은 다르다 — 오진 방지를 위해
  이 구분을 유지한다.
- R1/R2(예산 게이트) 라이브 재검증: fp8+res 조합은 262k·512k 모두 **동일한 floor 값**(−9,134MiB)을 냈다
  — KV 절대클램프(20,480MiB)가 context 길이와 무관한 고정값이기 때문이며, 예산 산식이 결정론적으로
  정확히 재현됨을 다시 확인했다.

## 3. R8(YaRN 번역기) 추가 검증 — 2건 누적

512k 그룹의 mmp 성공 4건 전부(`nv4-bf-512k-mmp`·`nv4-f8-512k-mmp`·`fp8-bf-512k-mmp`·`fp8-f8-512k-mmp`)가
동일 `hf-overrides`(YaRN factor=2) 위에서 정상 서빙됐다. R8은 이제 모델 변종(NVFP4/FP8)·KV dtype(auto/
fp8) 축 전체에서 재현 확인됐다.

## 5. 알려진 배선 결함(운영 관측, 누적)

- 메인 노드의 `--keep-up` 워치독·예산갱신 루프의 `&`(비-setsid) 결함은 이번 체크포인트 구간에서는
  **재발하지 않았다**(Monitor 기반 실행으로 전환한 이후 안정).
- **셀 8(nv4-bf-512k-res) 진행 중 중복 기동 발견**: 세션 압축(`/compact`) 직전에 백그라운드로 살아있던
  이전 호출이 있었고, 뒤이어 새로 기동한 호출이 예산 게이트에서 정확히 중복 로드를 거부(STOP, exit 3,
  부작용 없음)했다 — 게이트가 의도대로 작동함을 실증. 실제 서빙은 원래 살아있던 프로세스가 이어받았다.
- **서브측 ad-hoc 워치독의 journald 미도달 갭**이 셀 8에서 재확인됐고(수기 편입으로 보완), 셀 10에서는
  같은 종류의 사살이 시스템 L1 유닛(`unit:easy-vllm-memwatch`)에 의해 이뤄져 journald 정본 경로로
  자동 수확 가능함을 확인했다(`blackbox_events.py` 를 서브에서 직접 실행 후 이벤트 파일을 메인으로 회수).
  같은 실패 모드(watchdog kill)가 어느 워치독 인스턴스에 의해 집행되는지는 타이밍에 따라 갈린다.
