# lobotomized Claude Code의 프롬프트 절제 구조와 적용성

분석일은 2026-10-30 KST다. 로컬 `seed/lobotomized-claude-code`의 커밋 `f46b6d7b09d5e79c190f426f044762feb89abe43`을 대상으로 했다. 작업 트리는 깨끗했으며 최근 커밋 제목은 Claude Code 2.1.312용 override를 가리킨다.

**이 자료에서 채택할 것은 문장별로 필요한 정보를 가려내고, 편집 후에도 그 정보에 도달할 수 있는지 확인하는 방법이다.** Claude 내부 프롬프트를 패치하는 배포 방식이나 특정 모델의 기본 행동에 기대어 규칙을 지우는 판단을 이 프로젝트의 공통 헌장에 그대로 옮기는 것은 적합하지 않다.

이 보고서는 사용자 요청의 1단계 분석 결과다. 세 자료를 결합한 방법론과 현재 프로젝트의 적용 후보는 [헌장 간소화 방법론과 검증 종료 정책](harness_26103008_헌장_간소화_방법론과_검증_종료정책.md)에 정리했다. 헌장·하네스 코드·설치된 CLI는 이번 분석에서 변경하지 않았다.

## 분석 대상의 실제 구성

이 저장소는 실행 도구가 아니라 **Claude Code 프롬프트 조각의 대체 본문 모음**이다. 실제 패치는 별도 프로젝트 `tweakcc-fixed`가 담당한다. README와 작업 지침은 이 도구가 설치된 Claude Code의 프롬프트를 찾아 교체한다고 설명한다. 해당 패처의 구현과 원본 프롬프트 데이터는 이 로컬 분석 대상에 포함되어 있지 않다. [L1][L2]

각 Markdown 파일은 대체할 조각의 이름, 기준 `ccVersion`, 보간 변수 등을 HTML 주석에 기록하고 그 뒤에 대체 본문을 둔다. 본문을 비우면 원래 조각을 억제하는 용도이고, 파일을 없애는 것은 override를 제공하지 않는 별개 처분이다. 이 차이는 일반 프로젝트 문서의 삭제·이관과 동일하지 않다. [L1]

로컬 파일을 전수 집계한 결과는 다음과 같다. 본문은 파일 앞의 HTML 메타데이터 주석 하나를 제외한 문자열로 정의했다.

| 표면 | Markdown 파일 | 본문이 빈 파일 | 파일 크기 합계 |
|---|---:|---:|---:|
| `system-prompts-lcc/` | 14,523 | 216 | 12,270,971 bytes |
| `system-reminders/` | 42 | 5 | 15,759 bytes |

첫 표면에는 파일명 접두사 기준으로 tool result 7,134개, data 1,846개, slash command 1,479개, tool description 930개, system prompt 817개 등이 들어 있다. **파일 수나 전체 크기는 매 요청에 들어가는 컨텍스트의 크기가 아니다.** 실행 경로에 따라 사용되는 조건부 조각과 변경되지 않은 조각도 포함한다. [L1]

이 수치는 현재 체크아웃의 파일 계측이다. README의 2.1.280 기준 수치인 system prompt 21%, tool description 19%, agent prompt 30% 축소, 재작성 764개·전체 억제 199개와는 시점과 분모가 다르다. README의 Opus 5.5 약 5%, Fable 5.1 약 8% 요청 절감 주장도 이번에 재측정한 결과가 아니다. 원본 corpus와 실제 전송 기록 없이 현재 파일 크기로 절감률을 재계산할 수 없다. [L1]

집계 원문과 정의는 로컬 운영 근거 `docs/logs/constitution_research_26103008/source-inventory.json`에 보존했다. 내용 검토는 README·작업 지침과 아래의 대표 조각을 대상으로 했으며, 14,523개 본문의 의미를 전수 심사한 결과는 아니다.

## 절제 방법의 핵심

작업 지침은 먼저 문장이 전달하는 필수 주장을 분리하고, 같은 주장이 다른 조각에 남는지 확인하도록 한다. 고유한 정보만 남겨 짧게 고치거나, 남길 정보가 없으면 본문을 비우는 식이다. 여기서 중요한 단위는 파일이나 글자 수가 아니라 **없어졌을 때 행동이나 호출이 달라지는 정보**다. [L2]

특히 상시 제공되는 지침과 조건부 자료를 구분한다. 평소 읽히지 않는 기능 문서를 “잘 안 쓰는 기능”이라는 이유로 통째로 지워도 상시 컨텍스트를 줄인 효과는 없고, 그 기능이 필요해졌을 때 유일한 정보가 사라질 수 있다. 따라서 조건부 자료는 인터페이스 이름·제약·실패 형식을 유지하며 개별적으로 다듬는 것이 원문의 수정된 방침이다. [L2]

중복을 이유로 여러 파일을 동시에 줄일 때도 **편집이 끝난 상태에서** 주장이 남는지 확인한다. 작업 지침에는 A가 B를, B가 A를 남은 근거로 삼다가 양쪽에서 정보가 사라진 사례가 기록되어 있다. 다른 에이전트의 평가를 계속 반복하기보다, 정확한 API·명령·키 이름의 도달 가능성을 검사하고 그 검사로 판단할 수 없는 산문만 별도로 검토하자는 처방이다. 이 사례와 검사 성능은 해당 저장소의 서술이며 이번에 재실행한 관측은 아니다. [L2]

이 방법을 프로젝트 문서로 옮기면 “다른 파일에 있으니 삭제”가 아니라 “최종 문서 집합의 유일한 소유자가 무엇인지, 필요한 작업에서 두 하네스 모두 그 소유자를 찾을 수 있는지 확인한 뒤 중복 설명을 줄인다”가 된다.

## 이 자료만으로 확정할 수 없는 효과

README와 작업 지침은 특정 Claude 모델의 시스템 카드·프롬프팅 자료를 근거로 과도한 강조와 행동 보정 문구를 줄인다. 그러나 로컬 입력에는 그 판단에 사용했다는 별도의 카드 digest나 실제 전송 기록이 포함되어 있지 않다. “두 모델에서 기본적으로 잘하는 행동”이라는 판단을 Codex와 모든 제3자 모델로 확대할 수 없다. [L2]

Anthropic의 공식 프롬프팅 문서도 특정 모델에서 도구 사용을 과도하게 유도하는 문구를 완화하고, 다른 모델에 적용할 때 자체 평가로 다시 확인하도록 안내한다. 이는 모델에 따른 조정을 뒷받침하지만 프로젝트의 승인·정체성·개인정보·호스트 안전 계약을 없애도 된다는 근거는 아니다. [공식 프롬프팅 문서](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices)

실행 도구도 분리해 보아야 한다. 로컬 override 저장소에는 실행 스크립트 확장자 `.py/.js/.mjs/.ts/.sh`의 파일이 없다. 작업 지침이 참조하는 `checkFactCoverage.mjs`, 변수 binding 감사, 패치 적용과 smoke는 별도 패처 저장소의 절차다. 그러므로 이 저장소를 읽었다는 사실로 호환성 검사나 효과 검증을 통과했다고 말할 수 없다.

문서 자체에도 시점 차이가 있다. README는 2.1.280을 기준으로 수치를 설명하고 현재 커밋 제목은 2.1.312를 가리킨다. 작업 지침의 약 60% 축소 목표와 README의 요청 단위 5%·8% 주장도 같은 분모의 현재 관측으로 합칠 수 없다. **분량 목표와 이력 문구부터 현행 사실에 맞춰 검토해야 한다는 사례**다. [L1][L2]

## 이 프로젝트에 채택할 부분

현재 프로젝트는 `CLAUDE.md`를 공통 도메인 헌장으로 쓰고 Codex는 `AGENTS.md`를 통해 같은 계약에 들어온다. native CLI·세션·권한·결과 형식은 provider adapter가 소유한다. 따라서 공통층의 간소화는 도메인 규칙과 발견 경로를 다듬는 작업이어야 한다. Claude 바이너리만 교체하면 하네스별 환경이 달라져 이번 목적에 맞지 않는다.

| 채택 | 프로젝트에 맞게 바꿀 점 |
|---|---|
| 문장이 담당하는 고유 정보부터 식별 | 모델이 이미 안다고 추측해 지우지 않고 프로젝트의 보호 조건·업무 계약·소유자를 기준으로 분류 |
| 중복 설명 축약 | 최종 상태의 단일 소유자와 두 하네스의 발견 경로를 유지 |
| 상시 지침과 조건부 지식 구분 | 파일을 참조로 옮기는 것과 실제로 읽을 시점이 줄어드는 것을 별도로 확인 |
| 인터페이스·출력 계약 보존 | policy ID, 공개 진입점, manifest 사실, topology 헤더, 인용 앵커와 실제 검사 의존 문자열을 보존 |
| 제한된 검증 후 종료 | 정해진 수용 기준과 관련 회귀를 확인한 뒤 보고하며, 새로운 근거 없이 검수 에이전트나 검사를 반복하지 않음 |

채택하지 않을 것은 고정 축소 비율, 특정 모델의 기본 능력을 공통 불변식으로 보는 삭제, 보안 문구의 일괄 제거, Claude 내부 패처 설치, 이미 유효한 승인을 다시 요구하는 별도 승인 체계다. 원문 작업 지침의 대규모 삭제 절차도 이번 분석의 실행 지시가 아니며 이 프로젝트의 기존 작업 규칙을 대체하지 않는다.

## 최종 판단

**적용 검토를 진행할 수 있다.** 다만 “전두엽 절제”를 과감한 삭제량의 목표로 해석하면 원문이 강조한 고유 정보 보존과도 어긋난다. 적용 단위는 중복 설명과 불필요한 상시 로드이며, 보호 조건·필수 업무·정확한 인터페이스는 남는다. 간소화 뒤에는 같은 과업의 완료 판정이 유지되는지를 정해진 범위에서 확인해야 한다.

현재 자료는 이 방법의 참고 구현과 편집 근거를 제공한다. 이 프로젝트의 작업 시간·총 토큰·품질이 실제로 개선된다는 판정은 다음 단계의 비교 근거가 있어야 한다.
