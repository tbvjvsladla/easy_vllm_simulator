## 5. 이 수치를 읽는 법 — 네 가지 한계

1. **표본틀이 Verified 전체가 아니다.** Docker Hub 에 공개된 arm64 실행/채점 이미지는 Verified 500건 중
   **281건**뿐이다. aarch64 에서는 에이전트가 인스턴스 컨테이너 **안에서** 돌기 때문에 이 제약은 채점이
   아니라 인퍼런스에서 먼저 구속하며, 클라우드 채점으로도 우회되지 않는다. 표본 100건은 이 281건
   모집단에서 시드 고정으로 뽑았고, 그 결과 django·sympy 편중에 xarray 0건 · matplotlib 2건이다.
   django 비중이 큰 표본은 일반적으로 난이도가 낮은 쪽으로 치우친다.
2. **채점을 arm64 이미지로 했다.** SWE-bench 는 arm64 지원을 experimental 로 표기한다. 다만 인퍼런스도
   같은 arm64 환경에서 이뤄져 개발환경과 채점환경은 서로 일치한다.
3. **학습 데이터 오염을 배제하지 못한다.** Verified 과제는 2019~2023년 공개 PR 이고 대상은 2026년 모델이다.
   이 한계는 이 모델만의 것이 아니라 최신 모델의 모든 SWE-bench 측정에 공통이다.
4. **추론 강도가 배포자 공개수치 조건과 다르다.** 모델 README 는 공개 코드에이전트 벤치를
   `reasoning_effort=max` 로 측정했다고 밝힌다. 우리는 상주 서빙 정본인 **`high`** 로 쟀다 — 한 단계 아래다.
   참고로 배포자는 SWE-bench Verified 수치 자체를 공표하지 않으므로, 대조할 공식 수치가 존재하지 않는다.

검증은 발행 전에 붙였다. 채점 로그에서 `FAIL_TO_PASS`/`PASS_TO_PASS` 가 실제로 실행됐음을 확인했고,
채점 스크립트가 테스트 파일을 원본으로 되돌린 뒤 공식 test patch 를 적용한다는 점을 소스에서 확인했으며
(에이전트의 테스트 편집으로 점수를 얻을 수 없다), `FAIL_TO_PASS` 가 빈 인스턴스가 0건임을 확인했다.

## 6. 재현

표본과 실행은 결정론이다.

1. 표본: `princeton-nlp/SWE-bench_Verified` test 500건 → arm64 이미지 보유 281건으로 제한 →
   `random.Random(42)` 로 100건. 인스턴스 목록은 실행 디렉터리의 `instances_final100.ids.txt` 에 고정.
2. 인퍼런스: SWE-agent `run-batch`, 인스턴스 파일에 `image_name` 을 직접 지정(`sweb.eval.arm64.*`),
   `--num_workers=4`(서빙 동시성 상한과 정합).
3. 채점: SWE-bench 하네스를 **arm64 강제 래퍼**로 호출. 래퍼 없이 부르면 x86 이미지를 받아 전건 실패한다.

## 7. 부록 — 벤치 도구에서 발견한 결함 (같은 길을 갈 사람을 위해)

1. **SWE-bench 하네스는 아키텍처를 항상 `x86_64` 로 기본 지정한다.** `make_test_spec` 의 기본 인자가
   `arch="x86_64"` 이고 호출 체인 어디도 arch 를 넘기지 않는다. aarch64 호스트에서는 x86 이미지를 받아
   컨테이너가 즉사한다(`409 ... container is not running`). 함수 객체의 기본 인자만 `arm64` 로 교체하면
   전 호출부에 일괄 적용된다. 참고로 `USE_X86` 상수는 현재 코드에서 **참조되지 않는다** — 이 문제의
   원인이 아니다.
2. **SWE-agent 는 SWE-bench 이미지 이름에 `x86_64` 를 하드코딩한다.** 소스를 고치지 않고, 인스턴스 파일에
   `image_name` 을 실어 파일 기반 인스턴스 소스로 우회할 수 있다.
3. **litellm 경유 토큰 수신 계수를 믿지 말 것.** 이 모델 조합에서 `tokens_received` 는 다수가 0 으로 잡혔다.
   프롬프트 토큰만 신뢰 가능한 지표였다.
4. **`pgrep -f` 로 자기 작업을 감시하지 말 것.** 감시 셸의 커맨드라인이 패턴 자체를 담고 있어 영원히
   매칭된다. 우리는 이 함정으로 이미 끝난 실행을 2시간 43분 동안 "진행 중"으로 오판했다. PID 로 감시하라.
