## 4. 하네스 교정 라이브 실증

- **R1/R2(예산 게이트)**: fp8+res 조합 2건이 정확히 예측된 floor(−9,134MiB)로 로드 0초 차단 —
  게이트가 실제로 셀 루프 경로를 탄다(직전 캠페인의 "게이트가 있었는데 안 탔다" 침묵 누락 해소).
- **R2(PLE mmap 보정)**: 모든 mmap 셀에서 `weights_mib` 가 PLE 크기(48,828MiB)만큼 정확히 감산됨을
  확인(예: nv4-f8-262k-mmp 예산 로그 `ple=mmap(−48828MiB · index 파생)`).
- **R3(budget_renew)**: fp8-bf-262k-mmp·fp8-f8-262k-mmp 둘 다 이전에는 벤치 단계에서 사망했으나
  이번엔 5레벨 전부 완주 — 벤치 몫이 로드 게이트에 상주분으로 잘못 더해지던 결함이 해소됨.
- **R4(분류기 도달)**: nv4-f8-262k-res 의 워치독 사살이 `classify_cell.py` 로 정확히 분류됨(사인=
  `watchdog_kill_ack`, 출처=이벤트 시각대조).
- **R8(YaRN 번역기)**: 위 §2.
- **R5(image_digest)**: 전 셀 동일 digest 로 고정 확인 — "태그≠내용" 사고 재발 없음.

## 5. 알려진 배선 결함(운영 관측)

메인 노드의 `--keep-up` 워치독·예산갱신 루프가 `&`(비-setsid)로 무장되어, 서빙을 기동한 셸
프로세스 그룹이 조기 종료되면 함께 소멸하는 현상을 2회 관측했다(서브측은 SSH+setsid 라 생존).
매 발생 시 `setsid nohup`으로 즉시 재무장해 보호 공백을 최소화했다. 근본 수정(스크립트 자체의
main 워치독/갱신루프 launch 를 setsid 화)은 이 캠페인 범위 밖의 하네스 개선 후보로 남긴다.
