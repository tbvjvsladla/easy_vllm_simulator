# 멀티 4종 공식 vLLM 0.32.0 E2E 결과

상태: 네 모델의 신규 TP2 서빙·Full 측정, 힌트 4개 발행, 서비스 회수 및 캠페인 종료 완료.

캠페인은 `camp-26102919-codex-multi4-v032`이며, GB10 GPU 한 개씩 두 노드를 Ray TP2/RoCE로 사용했다. 사용자의 HITL 없는 실행 지시에 따라 모델별 context와 동시성을 정했고, 기존 싱글 캠페인 결과를 새 멀티 성공으로 합산하지 않았다. 새 모델 다운로드는 하지 않았다.

모두 health 200·실제 채팅 생성, lite 진입 게이트, 유효 Full·post-health를 통과했다. 선택된 네 셀은 합계 18회의 GuideLLM 반복을 완료했다. 대표값은 첫 완주 반복이며 평균이나 최고값으로 바꾸지 않았다. Full은 GuideLLM 0.7.3의 synthetic 입력 1,024/출력 256토큰, 요청 16·워밍업 2다. Qwen은 completions, 나머지는 모델 채팅 템플릿을 사용하는 chat 경로다. 설정 context 전체의 장문 정확도나 max-num-seqs 전부를 시험한 결과는 아니다.

성능 기준은 실패 뒤 낮추지 않았다. Qwen은 외부 E53.7/floor45.645, DS4F는 E46.5/floor39.525, EXL3는 E43.73/floor37.1705다. 모두 허용 오차 15%이며 외부 자료와 부하·소프트웨어 조건 차이를 각 힌트에 남겼다. Solar는 제한검색에서 적용 가능한 절대 E를 확보하지 못해 내부 roofline×MBU 기대치 9.19/floor7.81을 사용했다. Solar의 weak PASS는 외부 실측 기준 달성을 뜻하지 않는다. 네 셀 모두 explicit 권한이 아니므로 성능 인증서는 발행하지 않았다.

## 버전·실행 범위

공식 [v0.32.0 릴리스](https://github.com/vllm-project/vllm/releases/tag/v0.32.0)의 소스 SHA `5df63a7203cdb9328d824a27b682e77c7b9928be`로 고정했다. NGC 26.07/CUDA 13.3 기반이며 실제 torch는 `2.13.0a0+9186a08b2c.nv26.7.59513937`, 호스트 드라이버는 `580.178.04`다. 소스 빌드의 `0.32.1.dev0+g5df63a720…` SCM 표시는 다른 릴리스를 사용했다는 뜻이 아니다.

메인 소스 코어는 새로 빌드했다. 서브의 동일 SHA 기존 코어·의존성 근거는 재사용했고 필요한 자식 층은 각 노드에서 로컬 빌드했다. 완성 이미지 save/load 전송은 하지 않았다. SHA·torch·드라이버는 각 서빙 증명에서 노드 간 일치했으나 이미지 ID·부모 원장·SCM 날짜는 다르므로 전체 이미지 바이트 동등을 주장하지 않는다.

| 모델 | 선택된 주요 구성 |
|---|---|
| Qwen | resident PLE, target NVFP4 CUTLASS / draft FP8 Triton, MTP3, KV14GiB/노드, compile0 + decode graph |
| Solar | 공식0.32용 별도 Solar 런타임 플러그인, Marlin·EP, KV8GiB/노드, eager·spec off |
| DS4F0731 | B12X_MXFP4_MXFP8, DSpark5, KV10GiB/노드, graph; 셀ID의 spec7은 과거 이름 |
| EXL3 | 공식0.32 기반 SM12x 최소 이식, MCG2bit·file-backed Engram, DSpark3, KV8GiB/노드, eager |

EXL3는 순수 stock 기능이 아니라 별도 이식 변종이다. 최종 빌드는 PRE80~89/helper와 POST70/72/73/74/75/79를 적용했고, 의존성 보완 후 native 확장을 실제 재컴파일했다. 선택 성능 패치90~92는 미적용이며 densegemv는 꺼져 있다. POST74의 moeprep 코드와 PRE89의 graph 보완 코드는 적용됐지만 이번 eager·moeprep off 실행에서는 해당 경로가 비활성이다. 기존0.30 graph+10커널 자료와 이번 eager 최소 이식·합성 부하는 다르다. 새 모델 기능·Full 근거는 생겼지만 기존 모델 회귀 검증이 없어 아키텍처 원장의 `CANDIDATE` 지위는 유지했다.

Qwen은 CUTLASS B, Marlin C, native B12X H의 유효 Full을 보존하고 B를 발행 후보로 선택했다. H는 메모리 여유가 큰 대안이지만 backend·text-only·context·KV 등 여러 축이 함께 달라 단일 원인 대조가 아니다. 실패한 draft CUTLASS 및 FlashInfer B12X 안전중단도 별도 근거로 남겼다. B의 통계적 최속이나 최적성을 주장하지 않는다.
