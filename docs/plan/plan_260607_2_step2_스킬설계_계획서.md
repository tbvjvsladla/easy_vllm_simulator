## 2. 결정론적 해소 체인 (스크립트 분해)

런타임 워크플로 S1(resolve)을 아래 결정론적 스크립트로 구현한다. 각 스크립트는 **입력→출력이 검증 가능**해야 한다.

| # | 스크립트(가칭) | 입력 | 출력 | 비고 |
|---|---|---|---|---|
| ① | `resolve_torch_pin.py` | 대상 vLLM 버전 | torch 버전(예 2.11.0) | vLLM `pyproject.toml` `[build-system].requires`에서 추출(raw.githubusercontent) |
| ② | `resolve_ngc_tag.py` | torch 버전 | NGC pytorch 태그(예 26.03-py3) | **핵심 난제** — `NVIDIA_PYTORCH_BUILD_VERSION` 접두어 매칭. §3 결정 필요 |
| ③ | `resolve_wheel.py` | vLLM 버전·CUDA_VERSION·arch | 검증된 wheel URL | **GitHub Release 자산 실재 검증**(404 함정 방지: `manylinux_2_34` vs `2_35`, `cu129` vs `cu132`) |
| ④ | `regen_requirements.py` | 대상 vLLM 버전 | requirements.txt 제안 + diff | 기존 `check_reqs.py` 발전형. `common+cuda+build.txt` + `pyproject.toml` |

- ④는 기존 `configs/check_reqs.py`를 기반으로: (a) 대상 버전 파라미터화, (b) `build.txt` 추가,
  (c) 베이스 이미지가 이미 제공하는 패키지(torch/torchvision 등)는 "무시" 분류(devlog 260519 §6.1 교훈 반영),
  (d) MISSING/MISMATCH를 requirements.txt 패치 제안으로 출력.
- ③의 검증: `curl -s https://api.github.com/repos/vllm-project/vllm/releases/tags/v<버전>` 자산 목록에서
  실제 `cuXXX`·`manylinux_X_YY`·arch 태그를 확인해 URL을 구성(추측 금지). settings.local.json에 이미 허용된 API.

## 3. 핵심 결정 필요 — ②NGC 태그를 "기계적으로" 읽는 법

`NVIDIA_PYTORCH_BUILD_VERSION`은 NGC 컨테이너의 env/label에 박혀 있다. 결정론적으로 읽는 후보:

| 방식 | 방법 | 장점 | 단점/검증필요 |
|---|---|---|---|
| **A. skopeo inspect --config (권장 후보)** | `skopeo inspect docker://nvcr.io/nvidia/pytorch:<tag> --config` 로 env에서 `NVIDIA_PYTORCH_BUILD_VERSION` 추출 | 풀 pull 불필요, 결정론적 | skopeo 설치 필요. nvcr.io 인증(NGC API key) 필요 여부 확인 필요 |
| **B. NGC 카탈로그 API** | catalog.ngc.nvidia.com REST로 태그·메타 조회 | 공식 | 빌드버전 노출 형태·인증 확인 필요 |
| **C. 매핑 테이블 유지** | `reference.md`에 torch↔NGC태그 표 유지(26.01=2.10, 26.03=2.11 …) | 단순·오프라인 | 유지보수 부담. 신규 NGC 출시 시 갱신 |
| **D. 후보 pull+inspect** | 이미지 pull 후 `python -c "import torch"` | 확실 | 무거움(GB 단위) |

> **제안**: A(skopeo)를 1순위로 PoC, 실패 시 C(매핑 테이블, devlog가 이미 일부 기록)로 폴백.
> 이 부분은 작성 착수 전 **웹 검색/PoC + HITL**로 확정한다(설치 필요 도구는 설치정책 준수).

## 4. config.yaml 스키마 (초안)

```yaml
# upstream-version-watch 스킬 입력. 사람이 작성(영속). "업데이트" 지시 시 참조.
target_vllm_version: "0.22.0"        # 대상 vLLM 버전(채팅 지시로 덮어쓰기 가능)
cuda_version: "129"                  # 선택. 미지정 시 ③이 Release 자산에서 결정
smoke:
  single_node:
    model_name: "gpt-oss-120b"       # config 지정. 코드에 박지 않음
    nas_path: "/mnt/llm/Model/.../gpt-oss-120b"   # 사람이 사전 다운로드한 NAS 경로
  multi_node:                        # Step 4에서 사용
    model_name: "Qwen3.5-397B-A17B-NVFP4"
    nas_path: "/mnt/llm/.../Qwen3.5-397B-A17B-NVFP4"
```
- **하드 제약**: 모델이 `nas_path`에 없으면 스킬은 중단·보고(다운로드 금지).
- 단일/멀티 모델·경로 모두 여기서. Step 2는 single_node만 사용, multi_node는 Step 4.
