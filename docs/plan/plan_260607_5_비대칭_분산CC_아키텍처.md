## 0. 핵심 통찰 (사용자)
- 메인이 매 SSH 출력을 지리하게 파싱하는 건 비효율. 서브가 **자기 일을 자기가 책임지고 결과만 깔끔히 보고**.
- 서브 CC는 **성격이 완전히 달라야** 한다 — 범용 어시스턴트가 아니라 "체크리스트 실행 + 리포트" 전용.
- 서브는 원격저장소 불필요 → git 초기화/분리, 메인 전달 코드로만 생존.

## 1. 비대칭 두 에이전트
```
메인 CC (오케스트레이터, 192.168.100.10 / spark-a73e)
  - 컨테이너 구현 코드 전달(sync_to_sub.sh) · 서브 트리거 · HITL 게이트 · 아카이브 · origin push
  └─ ssh sub 'claude -p "<체크리스트>" --output-format json --bare \
              --permission-mode dontAsk --allowedTools "Bash(docker *),Bash(python3 *),Read,Edit"'
        ▼  (JSON report 1개)
서브 CC (빌드워커, 192.168.100.11 / spark-bdc9)
  - 자체 CLAUDE.md = 집중 페르소나(빌드·slave 서빙·모델별 envs/configs 자작 → JSON 보고)
  - 모델 다운로드 금지(NAS), 자동 실행(무프롬프트), raw 로그 대신 구조화 리포트
```

## 2. 통신 메커니즘 (CC 공식 — SSH + 헤드리스)
- **정석 = `ssh sub 'claude -p ... --output-format json'`**. Agent SDK Multiagent는 *같은 샌드박스/클라우드*용이라 머신 2대엔 부적합(공식 문서 명시). 근거: [headless](https://code.claude.com/docs/en/headless), [cli-reference](https://code.claude.com/docs/en/cli-reference).
- **무프롬프트 자동화 필수 3종**(없으면 SSH에서 권한 프롬프트 hang→타임아웃):
  `--bare`(로컬 훅/플러그인/MCP 스킵) · `--permission-mode dontAsk` · 명시적 `--allowedTools`.
- **구조화 리포트**: `--output-format json` (+ `--json-schema`로 스키마 강제) → 메인이 `jq`로 `.result`/`.structured_output` 파싱.
- 근거: [permissions](https://code.claude.com/docs/en/permissions), [permission-modes](https://code.claude.com/docs/en/permission-modes), [headless#structured-output](https://code.claude.com/docs/en/headless#get-structured-output).

## 3. 코드 범위 / 데이터 흐름 (확정)
- **메인 → 서브 (sync_to_sub.sh)**: 컨테이너 구현 코드만 — `Dockerfile`·`docker-compose.yaml`·`requirements.txt`·`configs/serve_runner.sh`(공통 런너) 등. 제외·보호: `.git`·`.claude`·`seed`·`docs`·`__pycache__`. (검증된 rsync, 기본 dry-run/`--apply`, 체크섬 검증.)
- **서브 자작**: 모델별 `envs/`·`configs/` 서빙 설정은 서브 CC가 체크리스트에 따라 자체 작성.
- **서브 → 메인 (아카이브)**: 서브 자작 설정 + 리포트를 메인이 회수해 **중앙 아카이브**(메인=정본 기록, origin push 주체와 일치).

## 4. 빌드할 산출물 (순서)
1. **서브노드 `CLAUDE.md`** (빌드워커 페르소나): 역할·NAS 금지·무프롬프트·JSON 리포트 규약. ← 출발점
2. **JSON 리포트 스키마**: 단계(build|serve|config)별 `status·duration·errors·artifacts·failure_class`.
3. **오케스트레이션 호출 래퍼**: 메인의 `ssh sub claude -p ...`(자동화 3종 + 스키마) = workflow 한 단계.
4. **서브 워크스페이스 리셋 절차**(#3): git-init/원격 분리, 메인 전달 코드 + 자작 configs만.
5. upstream-version-watch 멀티노드 path에 통합(인터뷰 결론) + Seed brownfield 반영.

## 5. HITL / 안전 경계
- HITL은 **메인 쪽**에 집중: 전달 게이트(sync `--apply`) · multi-smoke 실패 분류(Model-C). 서브는 자동 실행 후 보고.
- 서브 CC는 `--bare --permission-mode dontAsk --allowedTools`로 범위 제한(빌드/서빙/리포트만). 모델 다운로드 금지 규약은 서브 CLAUDE.md에 명시.
- smoke-before-push 유지: 단일+멀티 스모크 통과분만 메인이 origin push.
